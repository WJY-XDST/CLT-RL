日期：2026-10-11。工程根目录：`/home/aaa/studyRL/src/CLT-RL`。

按用户要求停用 IK 控制模式，并删除对应的完整训练目录（模型、日志、配置），同时清理依赖这些模型的评估、旧导出包和过时说明。当前直接主动关节位置策略和显式 VMC 保留。本次是退役清理，不是一次奖励或控制器调参。

## 1. 哪一种 IK 被删除

删除的模式是 `implicit_joint_reference`：策略输出虚拟腿摆角和腿长，五连杆逆解生成主动关节目标角，再由隐式关节 PD 执行。

保留两种执行链：

- `implicit_joint_position`：策略直接输出四个主动关节目标角和两轮目标轮速；隐式关节 PD 与独立重力前馈同时保留，不再经过 IK。当前训练使用此模式。
- `explicit_vmc`：策略输出虚拟腿参考，环境计算虚拟腿 PD、重力前馈及五连杆 `Jᵀ[F,T]`，下发腿关节力矩。

五连杆**正运动学、Jacobian、力／力矩映射**没有删除。它们仍用于实际腿部状态计算、VMC、重力前馈和诊断，并不等于 IK。

旧 IK 和当前关节角策略都可能具有 27 维观测、6 维动作，但字段含义不同，不能因为张量维度相同就混用权重。

## 2. 代码清理及接口配套

- 从 `five_bar_vmc.py` 删除 `five_bar_inverse`，从环境、训练和评估入口删除 IK 执行分支及相关参数路径。
- `leg_control.py` 仅允许上述两种保留模式；旧 `implicit_joint_reference` 配置明确报错，不能静默回退成另一种控制器。
- 删除只服务旧 IK 的跳跃任务、训练／检查脚本及诊断工具；移除对应任务注册和启动选项。键盘空格仍可记录跳跃请求，但当前没有可执行的跳跃策略。
- 默认 `mine_model/run.sh play` 改为选择**最近完成独立评估**的关节角检查点，生成配套回放参数。显式选择 VMC 时必须提供匹配的模型和配置，不与当前关节角模型混用。
- MuJoCo 接口与当前关节角动作、关节观测、重力前馈及总力矩限幅对齐，移除旧 IK 路径。显式 VMC 的 FK／力矩路径保留。
- `sim2real` 离线接口改为四个主动关节角参考和两轮轮速参考，旧 IK 导出包格式拒绝加载。这里只验证了上位机离线协议和导出一致性，**没有接通串口，也没有修改或运行下位机固件**。
- 记录生成器和监听文件列表不再引用已删除的 IK 脚本；报告监听器在写入前检查输出目录和控制模式，不能自动重建已清理的旧目录。

本次没有再次调整当前训练的 reward、PPO、PD 增益、重力前馈、车辆资产、物理限幅、物理步长或课程，也没有冻结任何策略输出。

## 4. 可恢复性与后台服务

采用 `gio trash` 移入桌面回收站，**没有清空回收站，也没有永久删除训练文件**。因此上面的字节数是从工程移走的数据量，不代表磁盘空间已经释放。

需要恢复时，可在文件管理器“回收站”按原位置恢复相应目录。恢复旧记录本身不会使当前代码支持 IK；若要重新使用历史 IK 权重，还必须匹配其旧源码、动作／观测定义和执行配置，不要直接用当前训练入口加载。

清理中发现旧 `mine-rl-optimization-journal.service` 仍读取 IK 目录，已停止并禁用其自动启动，服务文件保留为停用状态。没有停止或重启当前服务：
