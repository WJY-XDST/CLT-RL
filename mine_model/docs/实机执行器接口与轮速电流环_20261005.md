# 实机执行器接口与轮速电流环

用户确认：腿关节电机支持力矩控制，轮毂电机接受电流输入。当前正常运动训练继续；倒地自起任务已取消。本次增加独立执行器模块，没有修改训练的动作映射、奖励或驱动参数。

## 与当前策略的对应关系

RL策略在50 Hz输出六个归一化动作，顺序为左腿摆角、左腿长度、左轮速度、右腿摆角、右腿长度、右轮速度。腿目标必须经过当前运行参数中的高度混合、反馈、限幅和五连杆逆解，才能进入实机关节控制。不能把六个策略动作直接当作电机力矩或电流。

关节目标顺序为 `LB_joint / LL_joint / RB_joint / RL_joint`，相对新模型 base_link 的原始关节轴；腿力矩的基础规律为 `tau = Kp * (q_ref - q) - Kd * q_dot`。当前训练参考 Kp=300 Nm/rad、Kd=3 Nm/(rad/s)，腿电机仿真限幅10 Nm。腿控制不额外叠加旧显式VMC的腿力或重力前馈，因为训练时隐式Drive没有使用这些外加项。

轮子先从前向为正的目标速度映射到实际关节轴，仿真左右轴符号为 `[+1,-1]`，再计算 `error = omega_ref - omega`。PID先输出轮端力矩：`tau = Kp * error + integral - Kd * measured_acceleration`，最后 `I = tau / torque_per_amp`。右轴镜像与驱动器电流方向是两个独立标定项，不能重复翻转。

目前训练轮速阻尼2.0 Nm/(rad/s)，最接近的初始控制规律是P速度环，Ki=Kd=0。因此电流域比例增益应为 `2.0 / torque_per_amp` A/(rad/s)，而不是直接写2.0 A/(rad/s)。静态偏差明显且响应已稳定时再引入小积分项，不能仅靠增加积分纠正方向、单位或摩擦模型错误。

## 代码与配置

- `wheel_legged_isaaclab/deployment/actuator_bridge.py`：标准库实现，输入标定后的关节状态与目标，输出四个关节力矩、两个轮电流及轮速环诊断。
- `mine_model/config/real_actuator_template.json`：仿真参考参数与待填硬件标定项。当前未标定，加载函数主动拒绝该模板，不假设电流—力矩系数。
- `wheel_legged_isaaclab/tests/test_real_actuator_bridge.py`：单位、镜像、电流和力矩限幅、积分抗饱和、电流变化率、反馈过期、禁用与关节范围测试。

速度环带积分抗饱和、微分反馈滤波和电流变化率限制。速度目标跳变不直接产生微分冲击。启停时清空积分，所有PID内部量都以力矩单位计算。

## 必须用实测值补齐的内容

1. 电流输入的定义与单位：Iq、相电流、RMS或驱动器计数，不同定义不能共用未经换算的Nm/A。
2. 每侧有效轮端力矩/输入电流系数；若有减速器，要包括减速比和效率。
3. 每侧允许电流、轮端允许力矩、电流变化率，以及反馈最大年龄和控制周期上界。
4. 四个关节的实测零点、方向、有效角度范围、力矩命令的电机端/关节端定义与限幅。
5. 驱动器电流极性及轮速反馈方向。编码器电机端速度需要先换算到轮端rad/s。

模板中的300/3、轮P=2和10 Nm均为当前仿真参考，未证明适合硬件；应与最终选定策略的runtime_config同步，并用实际能力约束输出。

## 集成与验证顺序

先单独标定轮速度环，记录阶跃响应、超调、延迟、电流和速度反馈。在新模型MuJoCo中加入同样的采样周期、力矩/电流饱和、变化率与实测电机响应，再用固定权重重放基础运动。这一步尚未实施。

PhysX的隐式Drive与实机周期采样的显式力矩PD不具有相同的数值响应。项目早期显式控制曾承重失败，不能把本模块的代数公式测试通过当作整机站立验证通过。需要根据真实驱动响应决定是否调整执行器模型并追加训练；当前正常训练不会自动切换成实机控制器。

代码只生成命令，不含CAN/串口协议、IMU/编码器驱动、完整27维观测、RL推理和硬件状态机。通讯层必须检查异常、反馈过期和使能状态，并进入已经实测验证的接管模式。异常会清空内部状态并抛出，模块自身不会向电机发送停止命令。`enabled=False`返回零输出，只表示控制器禁用，不能把它作为整机保持站立的策略。

离线测试命令：`PYTHONPATH=wheel_legged_isaaclab python3 -m unittest discover -s wheel_legged_isaaclab/tests -p test_real_actuator_bridge.py -v`。
