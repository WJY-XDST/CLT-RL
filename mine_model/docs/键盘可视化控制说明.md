# 键盘可视化控制说明

## 启动

在终端执行：

```bash
cd ~/studyRL/src/CLT-RL
./mine_model/run.sh play
```

启动一个机器人、实时状态面板、键盘面板，并尽量按仿真时间实时播放。默认从当前自动训练输出的 `status.json` 中找到**最近一次完成评估**的模型，并加载同一轮的 `overrides.json`。正在训练时，不选择尚未完成评估的候选模型，也不默认回放历史 best 模型。该模型只是完成评估，不代表已经通过实机部署验收。

默认输出目录是 `mine_model/results/auto_training_implicit_20pct_20261004`；换训练分支时显式传入：

```bash
./mine_model/run.sh play --training_output /完整路径/自动训练输出目录
```

只想查看会加载哪个模型、不启动仿真：

```bash
./mine_model/run.sh play --dry_run
```

指定其他模型时，必须同时提供对应训练配置：

```bash
./mine_model/run.sh play \
  --checkpoint_path /完整路径/model_XXXX.pt \
  --overrides_json /完整路径/对应轮次/overrides.json
```

不要只指定权重却使用当前默认控制配置，尤其不要混用 `implicit_joint_reference` 和显式 VMC 力矩模式。键盘模块本身不会切换执行器或控制模式。

## 操作

等待机器人和面板加载完成，点击 Isaac Sim 窗口，再使用键盘。输入发生在仿真窗口，不是在启动终端中。不要在属性文本框里编辑时使用这些控制键。

|按键|指令|
|---|---|
|按住 W|前进，默认 `+0.5 m/s`|
|按住 S|后退，默认 `−0.5 m/s`|
|按住 A|左转，默认 yaw rate `+0.3 rad/s`|
|按住 D|右转，默认 yaw rate `−0.3 rad/s`|
|按住 Q|降低高度指令，间接缩短腿，默认 `0.01 m/s`|
|按住 E|提高高度指令，间接伸长腿，默认 `0.01 m/s`|
|松开 WASD|对应移动轴的目标归零|
|松开 Q/E|保持已调整的高度指令|
|L / Esc / 面板 Stop command|清除所有按住的键，前后速度和 yaw rate 指令归零；不退出软件|
|面板 Nominal height|停止移动指令，并恢复本次启动时的初始高度|
|空格|停止移动指令，记录一次原地跳跃请求；当前**不执行跳跃**|

允许组合按键，例如 W+A 同时前进和左转；相反按键同时按住时对应轴归零。重复按键事件不会叠加速度或重复触发跳跃。
带 Ctrl/Alt/Super 的组合快捷键不会被当作机器人移动指令；松键事件仍处理，防止残留运动按键。

高度上限/下限来自任务的 `commands.ranges_height`，在回放固定命令覆盖范围前读取。当前自己的模型通常为 **0.28～0.32 m**，初始高度 **0.30 m**；旧串联腿任务通常为 0.16～0.20 m。运行参数覆盖了这些值时，以实际加载的配置为准。

**Q/E 改的是策略已训练的机身高度命令，不直接改 action[1]/action[4]，也不锁定左右实际腿长。** 策略和已有控制链根据高度命令决定左右腿参考值；加减速、姿态补偿和接触状态仍可能令两腿长度不同。面板中的 height 是高度指令，不是实测腿长。

停止的是运动**目标**，不是强制冻结机体。前后速度指令仍经过环境已有的加速度限制，实际速度能否收敛到零取决于策略效果。默认手动模式直接给 yaw rate，松开 A/D 后目标为零，但不额外加入未经说明的世界航向 PI 补偿；零 yaw rate 不等同于严格保持世界航向。

切换到其他操作系统窗口后，手动控制会清空按键并将移动目标归零，恢复焦点后需重新按键。不把键盘控制用于实车安全急停。

## 调整键盘参数和记录变量

```bash
./mine_model/run.sh play \
  --keyboard_speed 0.3 \
  --keyboard_yaw_rate 0.2 \
  --keyboard_height_rate 0.005 \
  --trace_csv /tmp/mine_keyboard_replay.csv
```

CSV 沿用回放入口的速度、高度、pitch/roll、左右实际腿长、摆角、动作、轮速等字段，另加：

- `keyboard_active`：1 表示键盘已经接管任务指令；0 表示尚未接管或未启用。
- `keyboard_jump_requests`：累计空格请求次数，不代表完成跳跃次数。
- `cmd_x_target`：键盘期望前后速度；`cmd_x`：经过环境斜坡后的实际速度命令。
- `yaw_rate_requested`：用户请求的 yaw rate；若显式启用了已有 `--heading_feedback`，还应查看 `yaw_rate_applied`，不能把 PI 辅助效果当作纯策略效果。
- `height_cmd`：送入策略的高度命令；`base_height`：实测机身高度。

## 自动启动与固定对照测试

`wheel_legged_isaaclab/scripts/rsl_rl/play.py` 在普通轮腿 GUI 回放时自动创建键盘控制器，不需要单独开一个键盘进程。

- 没有指定 `--fixed_command` 时，默认从零前后速度、零 yaw rate、配置初始高度开始。
- 如果显式指定了固定指令或周期指令，按键前保持原回放流程；第一次控制按键后转为手动模式，周期指令不再覆盖手动输入。停止按钮也会接管指令。
- `--no_keyboard` 禁用自动键盘，用于可重复的固定/周期对照测试。
- headless、视频录制、启动定量采集和固定动作开环诊断默认不启用；这些模式强行启用键盘会报错。
- 所有环境共享同一套键盘指令；便捷入口默认只有一个机器人。
- `train.py` 和自动评估脚本没有接入键盘，不因人工回放改变训练分布、reward、obs 维度或当前后台训练。

例如对照测试沿用 `play_wheel.sh` 和对应模型/配置，并显式禁用键盘：

```bash
./play_wheel.sh --num_envs 1 --no_keyboard \
  --checkpoint_path /完整路径/model_XXXX.pt \
  --overrides_json /完整路径/对应轮次/overrides.json \
  --fixed_command 0.5 0 0.30 --constant_yaw_rate --live_stats --real-time
```

## 空格为何暂不让机器人跳

当前策略只接收前后速度、yaw rate、高度三类任务指令，没有已训练的跳跃模式。空格接口现在记录请求、将移动目标设为零，并在控制面板/终端提示 `NOT executed (untrained)`；不注入力矩脉冲、外力、瞬移或未经训练的腿动作。

后续要真正跳跃，应先定义起跳/腾空/落地控制和跳跃指令接口、训练并验证跳跃策略，然后把请求连接到已验证的模式切换。不能因为有一个按钮就认为平衡策略具备跳跃能力。

## 实现与验证范围

状态机和指令同步位于 `wheel_legged_isaaclab/scripts/rsl_rl/keyboard_control.py`，GUI 回放在 `play.py` 自动实例化；便捷入口选择模型逻辑位于 `mine_model/scripts/play_keyboard.py`。

输入使用 [Carbonite 输入接口](https://docs.omniverse.nvidia.com/kit/docs/kit-manual/110.1.2/carb.input/carb.input.IInput.html)，仅订阅仿真窗口键盘。控制按键在 Kit 快捷键之前处理并消费，防止空格同时暂停时间线；其他按键和鼠标事件放行。失焦检测使用 [IAppWindow.is_focused](https://docs.omniverse.nvidia.com/kit/docs/omni.appwindow/1.1.10/omni.appwindow/omni.appwindow.IAppWindow.html)。接口签名也与本地 Isaac Sim 5.1 SDK 核对。

已添加 CPU 单元测试，覆盖按下/重复/松开、组合按键、高度限幅、失焦停止、空格仅记录请求、命令与 27 维策略观测同步、原速度斜坡保留、事件消费/解绑和模型配置配对。实际 GUI 操作及策略执行效果仍须在回放中确认，单元测试不证明机器人速度/高度跟踪达标。
