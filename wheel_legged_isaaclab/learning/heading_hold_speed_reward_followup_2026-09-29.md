## 改动依据与具体代码

速度平方误差记为 `e² = (v_cmd - v_actual)²`。源工程以及移植版本此前使用：

```python
tracking_lin_vel_enhance = exp(-e² / tracking_sigma / 10) - 1
```

Python 连续除法从左到右计算。当 `tracking_sigma = 0.25` 时，等效分母是 `2.5`，并不是意图中的 `0.025`。在观测到的约 `0.065 m/s` 稳态误差处，该项约为 `-0.0017`，对策略区分欠速几乎没有帮助。本版定义 `tracking_sigma_enhance = 0.025`，改为：

```python
tracking_lin_vel_enhance = exp(-e² / tracking_sigma_enhance) - 1
```

同样误差处约为 `-0.155`；精确跟踪奖励、平方速度误差、静止样本比例和速度命令范围均不变。这个表达式相对开源原工程是**有意的奖励改进**，不是声称原工程公式写错。新增宽度参数的正值校验，避免非法配置。该项在速度误差为零时仍为 0，静止和运动命令使用同一公式，不增加特设静止奖励。

## 排除的改法

曾只把 `feedforward_force` 从 50 N 试调到 60 N，用旧 `model_2999.pt` 做隔离回放。右腿动作超过 0.85 的比例仍为 100%；静止机身高度从约 0.181 m 升到 0.193 m，前进段从约 0.190 m 升到 0.198 m。这说明不能把增加前馈当作已验证的饱和修复，因此已恢复 50 N。试验数据在同一 run 目录的 `feedforward60_probe.csv`，但它使用旧策略且初始扰动不同，仅用于排除明显不良的即时效果。

## 保留的控制逻辑

- `yaw_rate_error_sq` 平方惩罚仍启用，权重 `-5.0`。
- 航向保持仍以每回合初始朝向为目标，通过航向误差产生目标 yaw rate。
- 左右轮动作不强制相等，以保留载荷不对称时的补偿能力。
- 腿长目标仍硬限制在 `0.12–0.25 m`，左右腿长不被强制相等。
- 观测维度与动作维度不变；此轮奖励改动后采用从零训练，避免旧价值函数目标变化的混淆。

使用 8192 并行环境、独立 run 名称从零训练。训练中检查奖励是否为有限值、是否稳定保存检查点，以及超时/异常终止比例。训练后必须使用同样的两段命令回放，比较静止速度、0.5 m/s 实际速度、航向角误差、pitch、roll、机身高度、左右腿实际长度和动作饱和率。如果速度改善但姿态或腿长恶化，不应只凭总奖励宣布成功。
