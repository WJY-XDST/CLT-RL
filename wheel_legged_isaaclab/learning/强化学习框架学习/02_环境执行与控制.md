```python
def validated_wheel_action_limit(value):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        raise ValueError('wheel_action_limit must be a finite number in [1, 2]')
    value = float(value)
    if not math.isfinite(value) or not 1. <= value <= 2.:
        raise ValueError('wheel_action_limit must be a finite number in [1, 2]')
    return value
```

`value` 是配置中的轮动作包络，不是轮子的实测角速度。第一条判断先拒绝布尔值，再要求 int 或 float；Python 中 bool 与整数存在继承关系，因此需要单独排除，避免把 True 当成限幅 1 使用。

`float(value)` 统一数值类型，随后同时检查有限性与 `[1,2]` 的允许区间。NaN、无穷大及越界值会中止初始化，错误会留在配置入口处。返回值是校验后的浮点数。

回到构造函数，这次调用没有接收返回值，所以只完成启动校验，不会把 cfg 改写一遍。之后轮动作处理函数会使用相同规则取得 limit；当前 limit=1 时沿用轮动作的归一化包络。该规则不按高度、速度或转向选择不同限幅。

```python
def configure_reset_pose(cfg):
    """Resolve the actual spawn/reset template before creating the articulation.

    Historical checkpoint replay explicitly selects cad_zero_v0. A diagnostic
    fixture's deliberately elevated root (e.g. .9 m hanging) stays elevated.
    """
    profile = reset_profile(dict(leg_control_mode=cfg.leg_control_mode,
                                 joint_reset_profile=cfg.joint_reset_profile))
    pose = closed_chain_reset_pose(cfg.leg_joint_position_offset, cfg.five_bar_geometry,
                                   cfg.wheel_radius, MODEL['hip_z'])
    cfg.robot.init_state.joint_pos = (dict(pose['joint_positions']) if profile == NOMINAL_JOINT_RESET else {'.*': 0.})
    x, y, z = cfg.robot.init_state.pos
    if any(math.isclose(z, value, abs_tol=1.e-8, rel_tol=0.) for value in
           (MODEL['nominal_root_height'], pose['root_height_m'])):
        cfg.robot.init_state.pos = (x, y, pose['root_height_m'] if profile == NOMINAL_JOINT_RESET else MODEL['nominal_root_height'])
    return pose
```

```python
def reset_profile(config):
    mode = config.get('leg_control_mode', 'explicit_vmc')
    profile = config.get('joint_reset_profile', CAD_ZERO_RESET)
    if profile not in (CAD_ZERO_RESET, NOMINAL_JOINT_RESET):
```

`config` 在这里是临时构造的两个键的字典。缺少控制模式时按历史 `explicit_vmc` 解释，缺少 profile 时按 `cad_zero_v0` 解释。profile 只能是 `cad_zero_v0` 或 `joint_target_nominal_v1`；拼错名称不会静默回退。

#### 1.1.4 已知四个主动角，怎样补齐闭链初始姿态

源码：[joint_reset.py](../../wheel_legged_gym_isaaclab/joint_reset.py#L32)，第 32～60 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/joint_reset.py:32:60 -->

```python
def closed_chain_reset_pose(offset, geometry, wheel_radius=MODEL['wheel_radius'], hip_z=MODEL['hip_z']):
    """Active targets plus passive four-bar/parallelogram coordinates, in rad.

    L1 follows A->P, L2 follows C->P. In the authored parallelogram L3
    remains parallel to B, while S remains parallel to L2. The articulation
    includes L3_S closures, not the external S joints. Both wheels start at 0.
    """
    if len(offset) != 4 or not all(math.isfinite(v) for v in offset):
        raise ValueError('Require four finite reset motor offsets')
    if geometry['branch'] != 1 or geometry['scale'] <= 0:
        raise ValueError('Require the imported closed-chain assembly branch')
    result, heights, legs = {}, [], []
    for prefix, sign, qb, ql in (('L', 1., *offset[:2]), ('R', -1., *offset[2:])):
        a0, c0, p0 = _points(0., 0., sign, geometry)
        a, c, p = _points(qb, ql, sign, geometry)
        def direction_change(origin, old_origin):
            value = math.atan2(p[1]-origin[1], p[0]-origin[0])-math.atan2(p0[1]-old_origin[1], p0[0]-old_origin[0])
            return math.atan2(math.sin(value), math.cos(value))/sign
        l1, l2 = direction_change(a, a0), direction_change(c, c0)
        result.update({prefix+'B_joint': qb, prefix+'L_joint': ql,
            prefix+'L1_joint': l1-ql, prefix+'L2_joint': l2-l1,
            prefix+'L3_joint': qb-l2, prefix+'L3_'+prefix+'S_closure': l2-qb,
            prefix+'W_joint': 0.})
        wheel = tuple(geometry['scale']*v for v in p)
        heights.append(wheel_radius-hip_z-wheel[0])
        legs.append(dict(length_m=math.hypot(*wheel), angle_rad=math.atan2(-wheel[1], -wheel[0])))
    if abs(heights[0]-heights[1]) > 1.e-6:
        raise ValueError('A level reset needs matching left/right wheel support heights')
    return dict(joint_positions=result, root_height_m=sum(heights)/2., legs=legs)
```

输入 `offset` 的四个数按 `[LB,LL,RB,RL]` 排列，单位 rad。函数先拒绝不是四维、含非有限值、装配分支不符或比例非正的配置。这里已知主动角，只需求出与它们一致的被动关节和轮端位置；不是根据高度命令反求主动角的运行期 IK。

循环每次处理一侧，左侧 `sign=+1`、右侧 `sign=-1`，以匹配导出模型的镜像关节轴。`offset[:2]` 和 `offset[2:]` 各提供一侧的两个主动角。先算 CAD 零角的 `a0,c0,p0`，再算目标主动角下的 `a,c,p`，两次都调用 `_points()`。暂时停在这两行，先读它怎样求闭链的两圆交点：

源码：[joint_reset.py](../../wheel_legged_gym_isaaclab/joint_reset.py#L12)，第 12～29 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/joint_reset.py:12:29 -->

```python
def _points(q_b, q_l, sign, geometry):
    upper, lower = geometry['upper'], geometry['lower']
    theta_b, theta_l = (geometry['offsets'][0]+sign*q_b,
                        geometry['offsets'][1]+sign*q_l)
    c = (upper[0]*math.cos(theta_b), upper[0]*math.sin(theta_b))
    a = (upper[1]*math.cos(theta_l), upper[1]*math.sin(theta_l))
    delta = (a[0]-c[0], a[1]-c[1])
    d = math.hypot(*delta)
    if d < 1.e-7:
        raise ValueError('Singular reset linkage')
    along = (lower[0]**2-lower[1]**2+d*d)/(2*d)
    height2 = lower[0]**2-along*along
    if height2 <= 1.e-10:
        raise ValueError('Invalid reset linkage branch')
    normal = (-delta[1]/d, delta[0]/d)
    p = tuple(c[k]+along*delta[k]/d+geometry['branch']*math.sqrt(height2)*normal[k]
              for k in (0, 1))
    return a, c, p
```

`theta_b/theta_l` 把原始电机角换成几何杆角，包含 CAD 角偏置和左右符号。`c`、`a` 是两根主动上杆的末端，都是二元组；这里使用 Python `math` 处理一套名义几何，尚未创建 `[N,...]` 的 GPU 张量。

`delta=a-c`，`d=|delta|` 是两圆圆心距。两根下杆长度固定，轮端交点 `p` 到 `c` 和 `a` 的距离分别由 `lower` 约束。沿圆心连线的距离是 `(lower[0]²-lower[1]²+d²)/(2d)`，剩下的垂直距离平方就是 `height2`。`normal=(-delta_y/d,delta_x/d)` 给出单位法向，`branch` 决定取哪一侧的装配交点。

两处 `raise` 很关键：圆心重合或交点退化时直接拒绝重置模板，不用随意截断的几何把机器人放进场景。这个名义配置检查与运行期张量函数的数值保护、有效性标志各有用途。

带着 `(a,c,p)` 回到 `closed_chain_reset_pose()`。嵌套的 `direction_change(origin,old_origin)` 读取本轮循环里的新旧 `p/p0`，用两次 `atan2` 求杆方向的变化；`atan2(sin(value),cos(value))` 把角差包回主值区间，再除以 `sign` 转回原始关节轴约定。分别用上杆末端 `a/c` 作原点，得到两类下杆方向变化 `l1/l2`。

接下来 `result.update()` 不是把所有被动关节设成同一个角度：主动关节保存 `qb/ql`，被动相对角按 `l1-ql`、`l2-l1`、`qb-l2`、`l2-qb` 分别组合，轮关节起始角为 0。相邻构件的绝对方向与 USD 里关节的相对角必须区分，否则单改主动角、其余全零可能在闭链约束上产生初始冲突。

轮端坐标再乘几何比例，`wheel[0]` 对应此平面约定中的竖直坐标，因而支撑时根部高度是 `wheel_radius-hip_z-wheel[0]`。`math.hypot(*wheel)` 和 `atan2(-wheel[1],-wheel[0])` 只记录名义虚拟腿长、摆角。左右支撑高度若相差超过 `1e-6 m` 就拒绝水平重置；通过后返回三个字段：完整关节字典、左右平均根高度、两侧腿部诊断。

#### 1.1.5 带着 pose 返回配置函数，再回到构造函数

`configure_reset_pose()` 在名义关节 profile 下把完整字典复制给 `cfg.robot.init_state.joint_pos`；历史 CAD profile 则使用 `{'.*':0.}`。所以不能只看到资产默认配置中的零角就断言当前实际重置一定仍是所有关节零角，必须追到这个预处理函数和检查点保存的 profile。

`x,y,z = cfg.robot.init_state.pos` 解包根位置。只有原来的 z 接近模型名义高度或刚算出的姿态高度，才用对应 profile 的 z 替换。若诊断夹具特意把机器人悬在 0.9 m，这里会保留悬空设置；不是对任意场景强制落地。

```python
def validate_joint_position_map(offset, scale, margin):
    if len(offset) != 4 or len(scale) != 4:
        raise ValueError('Direct joint position actions require four offsets and scales in LB/LL/RB/RL order')
    if not all(math.isfinite(v) for v in offset):
        raise ValueError('Joint position offsets must be finite')
    if not all(math.isfinite(v) and v > 0 for v in scale):
        raise ValueError('Joint position scales must be finite and positive')
    if not math.isfinite(margin) or margin < 0:
        raise ValueError('Joint limit margin must be finite and nonnegative')
```

`offset` 与 `scale` 必须各有四个数，列顺序固定为 LB、LL、RB、RL。offset 给出零动作对应的关节角；scale 给出每列动作的角度幅度。它们是创建环境时的配置序列，后面的 `[N,4]` 动作才包含 N 个环境。

偏置只要求有限；尺度还要求严格大于零。这样后面用 `(target-center)/amplitude` 反算有效动作时不会除零，动作尺度也不会暗中反转关节方向。margin 是关节角安全余量，必须有限且非负，单位仍是 rad。

函数正常结束时返回 None。它只检查映射配置，不计算 target，也不写入执行器。通过后返回 `_validate_configuration()`，后续 `joint_position_targets()` 才把动作、这三项配置与实际关节限位组合起来。

```python
def validate_tracking_goal_reward_config(rewards, leg_control_mode):
    """Validate opt-in bounds without coupling disabled legacy rewards to PD."""
    goal_scale = getattr(rewards, 'tracking_goal_violation', 0.)
    goal_cap = getattr(rewards, 'tracking_goal_penalty_clip', 40.)
    if not math.isfinite(goal_scale) or not -2. <= goal_scale <= 0.:
        raise ValueError('Tracking-goal feedback must be finite, nonpositive and bounded by minus two')
    if goal_scale and leg_control_mode != 'implicit_joint_position':
        raise ValueError('Tracking-goal feedback requires direct joint-position PD')
    if not math.isfinite(goal_cap) or goal_cap <= 0 or goal_cap < 24.5 * abs(goal_scale):
        raise ValueError('Tracking-goal cap must retain feedback up to 26 times the original tolerances')
    component_scale = getattr(rewards, 'tracking_goal_component_violation', 0.)
    component_cap = getattr(rewards, 'tracking_goal_component_penalty_clip', 200.)
    if not math.isfinite(component_scale) or not -1. <= component_scale <= 0.:
        raise ValueError('Component tracking feedback must be finite and in [-1,0]')
    if component_scale and leg_control_mode != 'implicit_joint_position':
        raise ValueError('Component tracking feedback requires direct joint-position PD')
    if (not math.isfinite(component_cap) or component_cap <= 0
            or component_cap < 7. * 24.5 * abs(component_scale)):
        raise ValueError('Component cap must retain all seven concurrent errors up to 26 times tolerance')
```

输入 rewards 是奖励配置对象，leg_control_mode 是本次环境的控制模式。`getattr(..., default)` 读取可选系数及其裁剪上限；默认值保证缺少可选字段时按照关闭或既定上限处理。

前半段检查最大超差惩罚：系数必须有限且处于 `[-2,0]`；只有启用时才要求直接关节 PD 模式。goal_cap 是代价的裁剪上限，必须为正，并与系数幅值匹配。`24.5 * abs(goal_scale)` 来自通用超差代价的幅度要求，避免配置的裁剪上限过小而让较大误差过早失去反馈。

后半段对分量超差惩罚做同类检查，但系数范围为 `[-1,0]`，上限要求带有 `7`，对应速度、偏航、高度、腿长、腿角、轮速与姿态七个分量同时贡献代价。两个 cap 都是训练奖励配置，不是验收误差阈值。

正常返回 None，不会因为检查了配置就启用奖励。当前两项系数都为零，后续奖励计算会跳过它们。最大超差是同一环境同一步内指标间的比较；这里没有把某个高度、速度或偏航方向识别出来另行加罚。

```python
def grouped_task_ids(env_ids, phase=0, dedicated_standing_count=None):
    """Keep dedicated global IDs standing and rotate only the remaining motion roles.

    None preserves the historical six-role rotation. A nonnegative count reserves
    IDs [0, count) for standing; the other IDs rotate through five motion roles.
    Passing global rather than batch-relative IDs also preserves partial resets.
    """
    if dedicated_standing_count is None:
        return (env_ids + phase) % len(TASK_NAMES)
    if (isinstance(dedicated_standing_count, bool)
            or not isinstance(dedicated_standing_count, int)
            or dedicated_standing_count < 0):
        raise ValueError("Dedicated standing count must be a nonnegative integer")
    motion_groups = 1 + (env_ids - dedicated_standing_count + phase) % (len(TASK_NAMES) - 1)
    return torch.where(env_ids < dedicated_standing_count, 0, motion_groups)
```

调用者先计算专用站立数量 K：只有 `grouped_training` 和 `fixed_standing_groups` 都启用，才取 `int(N*standing_env_fraction)`；否则传 `None`，沿用历史六组轮换。N 是实际创建的环境数，不是某个配置文件里固定的 4096。

传入的 `torch.arange(self.num_envs)` 是全局环境 ID `[0,...,N-1]`。第一次调用只做初始化计数打印，没有传 `device`，因而这批小规模分组统计在默认设备上构造；后面的命令抽样会传入实际设备上的环境索引。函数里的 `torch.where` 和取模跟随输入张量设备，算法本身没有强制 CPU 或 CUDA。

`dedicated_standing_count=None` 时，`(env_ids+phase)%6` 让所有 ID 在六种任务中轮换。给定 K 时，编号 `<K` 永远返回角色 0，其他编号先减去 K、加 phase，再 `%5+1`，只在五种运动角色中轮换。对非法 K 的检查还特意拒绝布尔值。

以教学例子 N=8、K=2 为例，phase=0 的结果是 `[0,0,1,2,3,4,5,1]`，phase=1 变为 `[0,0,2,3,4,5,1,2]`。前两台始终静止，其余共享同一个 Actor，只是命令任务不同；这不是六套策略。

函数返回与输入 ID 同长的一维角色张量，没有改机器人状态。回到构造函数，`torch.bincount(...,minlength=len(TASK_NAMES))` 数出六个角色各有几台，`zip` 与 `dict` 只组成打印内容。真正按角色抽速度还在后面的命令重采样里；再次遇到分组函数时回到此处核对即可。

```python
def joint_position_targets(actions, offset, scale, limits, margin=0.0, *, validate=True):
    """Four normalized policy coordinates -> raw CAD motor angles [rad].

    No virtual-leg reference, IK, height feedback or explicit joint PD
    participates in this position map. Gravity feedforward is a separate
    effort channel, never an angle offset. Limits are the articulation's
    hard position limits, intersected with the configured action envelope.
    """
    # 纯张量函数，不调用 LAB/PhysX：调用方传入 Articulation.data.joint_pos_limits。
    # actions 为 [N, 4]，limits 为 [N, 4, 2]；四列顺序是 LB、LL、RB、RL。
    import torch
    if actions.ndim != 2 or actions.shape[1] != 4:
        raise ValueError('Expected a batch of four active-joint actions')
    if validate:
        validate_joint_position_map(offset, scale, margin)
    if limits.shape != (*actions.shape, 2):
        raise ValueError('Joint limits must have shape [num_envs, 4, 2]')
    if validate and (not torch.isfinite(limits).all() or not ((limits[..., 1] - limits[..., 0]) > 2 * margin).all()):
        raise ValueError('Joint limits must be finite and wider than twice the safety margin')
    center, amplitude = actions.new_tensor(offset), actions.new_tensor(scale)
    # 允许区间是「nominal±动作尺度」与「USD 关节角限位减 margin」的交集。
    # 全部用 rad；它不是 CAD 限位块接触包络，也不是虚拟腿长的硬限制。
    lower = torch.maximum(limits[..., 0] + margin, center - amplitude)
    upper = torch.minimum(limits[..., 1] - margin, center + amplitude)
    if validate and (not (lower < upper).all() or not ((center >= lower) & (center <= upper)).all()):
        raise ValueError('Joint action envelope and safe articulation limits must contain the reference pose')
    normalized = torch.nan_to_num(actions, nan=0., posinf=1., neginf=-1.).clamp(-1., 1.)
    target = torch.maximum(torch.minimum(center + normalized * amplitude, upper), lower)
    # 第二项将最终角度反算为有效归一化动作，供 last_actions 和奖励使用。
    # 这里只生成参考；LAB set_joint_position_target() 和隐式 PD 在环境中执行。
    return target, (target - center) / amplitude
```

`actions` 形状是 `[N,4]`，`limits` 是 `[N,4,2]`，最后一维保存每个关节的上下限。

`actions.new_tensor(offset)` 根据动作张量创建同设备、合适数据类型的常量，避免把 CPU 常量与 GPU 动作混算。

目标区间先取两个范围的交集：

```text
动作范围：offset − scale 至 offset + scale
关节范围：hard_lower + margin 至 hard_upper − margin
最终下限：两类下限的较大者
最终上限：两类上限的较小者
```

随后计算 `offset + clamp(action,-1,1)×scale`，再限制到最终角区间。

例如 LB 偏置为 −0.0707452938 rad、尺度为 0.3 rad，动作 0.5 对应未触及角限位时的目标：

```text
q_target = −0.0707452938 + 0.5 × 0.3
         =  0.0792547062 rad
```

这是一个角度映射，与高度命令没有直接函数关系。高度通过观测和奖励影响 Actor 学习，而不是在这行代码里被转换为关节角。

#### 1.5.2 在函数内部读懂第二个返回值 `applied`

如果未裁剪目标是 0.25 rad，但关节安全上限是 0.20 rad，最终执行的是 0.20 rad。反算 `applied=(target-center)/amplitude` 后，历史动作中记录的是实际参考。

这有助于避免动作变化惩罚对一段根本没有执行的角度变化重复计分。但原始输出仍保存在 `_raw_actions`，用于观察饱和和计算相关代价。

#### 1.5.3 接着读广播、两类区间和逐元素限幅

`actions.new_tensor(offset)` 生成 `[4]` 的中心向量，且设备和 dtype 跟随输入动作。`amplitude` 同样是 `[4]`，与 `[N,4]` 相乘时会沿环境维广播，给 N 台机器人使用同一组四个动作尺度。

`limits[...,0]` 与 `limits[...,1]` 分别取 `[N,4,2]` 最后一维的下限和上限，得到两个 `[N,4]` 矩阵。`...` 保留前面的环境与关节维，没有把它们展平。

`torch.maximum(limits[...,0]+margin, center-amplitude)` 选择更严格的下限；`torch.minimum(limits[...,1]-margin, center+amplitude)` 选择更严格的上限。一个来自资产，一个来自策略动作映射，最终只允许两者交集。

以下只是一列关节的教学数值，不是本机器人某个实测关节参数：中心 0.10 rad、尺度 0.30 rad、资产限位 `[-0.20,0.30]` rad、安全余量 0.02 rad。

```text
动作自身允许角度：[0.10-0.30, 0.10+0.30] = [-0.20, 0.40]
资产减余量后区间：[-0.20+0.02, 0.30-0.02] = [-0.18, 0.28]
最终允许交集：    [-0.18, 0.28]
输入动作 a=0.8：  0.10 + 0.8×0.30 = 0.34 rad
最终目标角：      min(max(0.34,-0.18),0.28) = 0.28 rad
有效动作 applied：(0.28-0.10)/0.30 = 0.6
```

这解释了为什么 `_actions` 在执行映射之后可能与前面仅做 ±1 clamp 的值再次不同。这里实际执行参考对应 0.6，而 `_raw_actions` 仍能保存 0.8。

#### 1.5.4 从本次 `validate=True` 理解以后为什么传 `False`

当前这次构造调用没有显式传 `validate`，因此执行默认的 `validate=True`，逐项检查偏置、尺度、余量和实际限位。等这里成功返回以后，运行期的每个物理子步才可以传 `validate=False`，避免重复执行需要把 GPU 归约结果转换为 Python 判断的检查。

例如 `torch.isfinite(limits).all()` 在张量侧做归约，随后 Python 的 `if` 要读取这个结果，会引入主机等待。8192 个环境、每秒 200 个物理子步下，反复做同一份不变配置验证会增加开销。

但 `validate=False` 没有跳过形状检查、NaN 清洗、归一化动作 clamp、允许区间求交或最终目标角 clamp。它不是解除机械限位的开关。

如果以后确实动态修改关节限位、偏置或尺度，就必须重新考虑这些不变量何时验证，不能沿用“启动时已经检查过，所以永远不会改变”的假设。

#### 1.5.5 两个返回值产生后，回到原来的构造调用

第一次调用读完，返回的位置是上面 `__init__()` 中那条没有赋值号的函数调用。偏置在安全区间内时，零动作会算出 `target=offset`、`applied=0`，但调用方没有接收这两个返回值。因此它只完成启动校验，**没有把算出的目标写进机器人，也没有改写 `_joint_position_ref_applied` 这块零缓存**。

原因要从函数内部核对：`new_tensor()`、`minimum()`、`maximum()` 和算术表达式生成结果，没有 `actions[...] = ...` 这样的原地写入；函数里也没有 `set_joint_position_target()` 或 `write_joint_state_to_sim()`。所以“计算一次零动作目标”“保存一份参考缓存”“修改实际重置关节角”是三步不同的操作。实际闭链初始模板由构造函数开头的 `configure_reset_pose()` 准备。

现在才返回构造主线：继续建立失败计时、回合奖励统计和命令重采样时钟。真正有策略动作以后，第七节会再次调用同一个映射函数，并接收、保存和提交返回值；那里不再重复函数内部的推导。

```python
    required = ('relative_error', 'speed_absolute_m_s', 'yaw_absolute_rad_s',
                'wheel_absolute_rad_s', 'leg_angle_design_range_rad', 'body_p95_deg',
                'minimum_height_fraction')
    for key in required:
        value = criteria.get(key)
        if type(value) not in (float, int) or not math.isfinite(value) or value <= 0:
            raise ValueError('Invalid tracking-goal criterion: ' + key)
    if criteria['relative_error'] > .1 or criteria['minimum_height_fraction'] > 1:
        raise ValueError('Tracking feedback requires the original ten-percent gate')
    return criteria, dict(path=str(path.resolve()), sha256=hashlib.sha256(content).hexdigest(),
                          criteria=criteria)
```

`path` 是可选路径。未传入时，函数从自己的文件位置定位工程中的 `mine_model/config/tracking_acceptance.json`。`content` 保存实际读到的原始字节，`criteria` 保存解析得到的字典；保留原始字节可以对本次真正使用的文件内容计算 SHA-256。

`required` 列出奖励需要的七个判据字段。循环变量 key 每次选一个字段，value 取出对应数值；缺字段、布尔值、非数值、NaN、无穷大或不为正，都会在这里报错。接着检查 relative_error 不超过 0.1，minimum_height_fraction 不超过 1，防止训练评分误读了一份放宽的判据。

最后返回 `(criteria, evidence)`。criteria 供奖励及质量权重计算读取；evidence 包含真实绝对路径、原始字节的内容指纹和同一份判据字典。它记录来源，不是模型测得的误差，也不是验收通过标志。

返回构造函数后，两个对象按位置写入 `_tracking_goal_criteria` 和 `_tracking_goal_evidence`。加载一次后，控制循环直接使用内存中的判据；这一过程不更新模型。文件缺失或配置非法时会抛异常，不会静默地用空字典继续训练。

两个返回值按位置赋给 criteria 与 evidence 对应的成员。下面是只解释分支的教学例子，未修改训练配置：

| 第一项系数 | 第二项系数 | 是否加载 |
| --- | --- | --- |
| 0 | 0 | 否 |
| -0.1 | 0 | 是 |
| 0 | -0.1 | 是 |
| -0.1 | -0.1 | 是 |

带着两个返回值回到当前构造函数，下一行继续为已启用的可选奖励准备回合统计。

##### 第四步：给启用的可选项补齐统计张量

循环变量 `key` 依次是两个奖励项的名称字符串。`getattr(self.cfg.rewards, key)` 按名称取相应系数；只有非零项才建立 `self._episode_sums[key]`。

每个新增值仍为初始全零的 `[N]` 浮点张量。这样 `_get_rewards()` 后面增加这些可选 reward 时，累加器已经有对应键。循环只遍历两个奖励名称，并没有用 Python 逐台遍历 N 个机器人。

例如 key 为 tracking_goal_violation 时，getattr(self.cfg.rewards, key) 与读取同名配置属性等价，得到的是系数。若实际 N=8192，缓存形状为 [8192]，ID=100 对应第 100 号索引行，保存该环境累计的一个标量。这里使用 N 表达实际数量，并没有把代码固定为 8192 行。

##### 第五步：准备当步奖励和诊断缓存

`self._last_reward_terms: dict[str, torch.Tensor] = {}` 保存**最近一次控制步**的各项奖励张量。字典初始化为空；`_get_rewards()` 计算完成后，用各项 `value.detach()` 更新它。每项通常为 `[N]`，可用于查看本步到底是哪项奖励在起作用。它每步被替换，而 `_episode_sums` 跨多个控制步累加；两者时间范围不同。

`self._tracking_diagnostics: dict[str, float] = {}` 保存便于写日志的聚合统计，值为普通标量，例如各任务组的速度误差、yaw 误差和奖励裁剪比例。当前 `_get_rewards()` 在字典尚为空或控制步计数到 100 的倍数时更新它，再由观测返回路径合入日志。它没有直接参与动作执行或奖励求和，也不应被解释成每个环境都拥有的一条完整误差轨迹。

这里的类型注解说明字典预期放什么；`{}` 本身只创建空字典，没有提前分配这些奖励和诊断数值。

##### 第六步：记录每个环境上一次重采样命令的时刻

`self._command_resample_step` 是形状 `[N]`、类型 `torch.long` 的整数张量，初始化全零。每一行保存对应环境**上次重采样命令时的控制步计数**，单位是步，不是秒。

之后 `_resample_commands_for(env_ids)` 先生成命令，再执行 `self._command_resample_step[env_ids] = self.common_step_counter`，只更新本次换命令的那些环境。reset 诊断用“当前控制步 − 这份时间戳”判断故障离上次换命令有多远；需要换算秒时再乘 `step_dt`。它本身不会让命令重采样，也不会改变命令范围。

教学例子：全局步 250 给全部环境重采样，时间戳都为 250；到第 400 步，仅 ID=100 因 reset 重采样，就只把该行改为 400。其他环境已经过 150 步，在 step_dt=0.02 s 时对应 3 s，ID=100 则刚换命令。

| 相关变量 | 数据范围 | 作用 |
| --- | --- | --- |
| _last_grouped_command_phase | 一个全局整数 | 记录任务阶段是否已经处理。 |
| _command_resample_step | 每环境一个整数，共 [N] | 记录各自最近命令采样的控制步。 |

全局任务阶段与每环境时间戳分别服务于任务组织和诊断，部分 reset 后各行时间戳可以不同。

至此，当前训练步骤完成了三类准备：奖励用到的判据、当前步与整回合的统计容器、每环境的命令时间戳。下一步构造函数返回，随后 wrapper 的首次 reset 才真正准备第一批训练状态。

### 1.6 基类已有 `actions`，为什么任务还使用 `_actions`

基类在配置 Gym 空间时会分配 `self.actions`。本任务另外建立 `_raw_actions`、`_actions` 和 `_last_actions`，并在自己的回调中使用它们。

阅读时要按完整变量名追踪。不能因为两个名字都含 `actions`，就认为写入 `self.actions` 一定会改掉 `_actions`，也不能把 `single_action_space` 这个空间描述对象当成动作数值本身。

跨文件衔接是：配置中的 `action_space=6` → 基类建立单机器人动作空间 → 子类读取 `single_action_space.shape[0]` → 为 N 台机器人分配 `[N,6]` 的数值缓存。

```python
def synchronize_actuator_limits(cfg):
    """Make software clipping, USD drives and Isaac actuator limits agree."""
    for group, limit in (("legs", cfg.leg_effort_limit), ("wheels", cfg.wheel_effort_limit)):
        if not math.isfinite(limit) or limit <= 0:
            raise ValueError(f"{group} effort limit must be positive and finite")
        actuator = cfg.robot.actuators[group]
        actuator.effort_limit_sim = limit
        # ImplicitActuator raises for contradictory legacy/current fields.
        actuator.effort_limit = None
```

输入 cfg 是同一份环境配置对象。顶层 `leg_effort_limit`、`wheel_effort_limit` 是任务使用的腿/轮力矩上限；`cfg.robot.actuators` 则是交给资产初始化的执行器配置字典。两处分别存在，因此需要项目代码显式同步。

循环只处理两组配置：group 依次为 `legs` 和 `wheels`，limit 分别取对应的顶层上限。它没有逐台遍历 N 个环境，也没有根据机器人所处高度或速度切换参数。有限性与正值检查在写入之前完成，非法标定会直接报错。

`actuator = cfg.robot.actuators[group]` 取得嵌套配置对象的引用。写 `actuator.effort_limit_sim = limit` 会更新原来的 cfg，而不是生成一份独立副本。这样创建 Articulation 时读取的求解器驱动上限，与任务后续使用的上限来自同一项硬件配置。

`actuator.effort_limit = None` 清掉旧接口字段，留下 `effort_limit_sim` 作为本次明确设置的字段。当前 Isaac Lab 会拒绝互相矛盾的新旧字段；这里消除配置冲突，并没有将实际力矩上限设为 None。

返回值是 None，因为结果通过修改 cfg 内部的执行器对象传递。回到 `_setup_scene()` 后，下一步确定腿关节增益，再执行 `Articulation(self.cfg.robot)`。必须按这个顺序，让资产初始化一开始就拿到正确上限；后面单改 Python 配置并不会自动重建已经创建的驱动。

| --- | --- | --- |
| `cfg.leg_effort_limit` | `cfg.robot.actuators['legs'].effort_limit_sim` | 腿执行器初始化 |
| `cfg.wheel_effort_limit` | `cfg.robot.actuators['wheels'].effort_limit_sim` | 轮执行器初始化 |

本函数只同步力矩上限配置。关节角、目标轮速、速度上限和增益分别沿各自的配置与动作链路处理。

```python
def leg_drive_gains(mode, stiffness, damping):
    """VMC uses external efforts, never an additional joint-position PD."""
    require_leg_control_mode(mode)
    if mode == 'explicit_vmc':
        # 环境已通过 Jᵀ[F,T] 计算反馈力矩，LAB 关节驱动不能再叠加一套位置 PD。
        return 0.0, 0.0
    if not math.isfinite(stiffness) or stiffness <= 0 or not math.isfinite(damping) or damping < 0:

    return float(stiffness), float(damping)
```

```python
def relocate_collision_groups(stage, env_paths):
    from pxr import Sdf, UsdPhysics

    source_robot = env_paths[0] + '/Robot'
    source_path = source_robot + '/collision_filters'
    source = stage.GetPrimAtPath(source_path)
    if not source or not source.IsActive():
        return
    destination = '/World/mine_collision_filters'
    groups = [p for p in source.GetChildren() if p.IsA(UsdPhysics.CollisionGroup)]
    if not groups:
        return
    # CollisionGroup objects cannot be replicated by the PhysX cloner. Put
    # three shared groups on the scene and explicitly include every clone's
    # shapes; ground stays outside them, preserving ground contacts.
    for prim in groups:
        group = UsdPhysics.CollisionGroup.Define(stage, destination + '/' + prim.GetName())
        original = UsdPhysics.CollisionGroup(prim)
        for attribute in prim.GetAttributes():
            if attribute.HasAuthoredValueOpinion():
                group.GetPrim().CreateAttribute(attribute.GetName(), attribute.GetTypeName(),
                                               custom=attribute.IsCustom()).Set(attribute.Get())
        filtered = original.GetFilteredGroupsRel().GetTargets()
        group.CreateFilteredGroupsRel().SetTargets([
            Sdf.Path(destination + '/' + path.name) for path in filtered
        ])
        includes = original.GetCollidersCollectionAPI().GetIncludesRel().GetTargets()
        suffixes = []
        for path in includes:
            if not str(path).startswith(source_robot + '/'):
                raise ValueError('Stop collision group includes a shape outside the source robot')
            suffixes.append(str(path)[len(source_robot):])
        group.GetCollidersCollectionAPI().CreateIncludesRel().SetTargets([
            Sdf.Path(env_path + '/Robot' + suffix)
            for env_path in env_paths for suffix in suffixes
        ])
    source.SetActive(False)
```

这里需要展开的是本项目怎样组织闭链止挡的碰撞过滤。stage 是当前场景，env_paths 是克隆环境根路径列表。`source_robot` 由第一个环境拼出源机器人路径，`source_path` 指向其 collision_filters；若源分组不存在、未启用或没有 CollisionGroup 子节点，函数直接返回。

destination 固定在 `/World/mine_collision_filters`。原因是这些碰撞分组不能留在由 PhysX 复制的机器人子树里。`groups` 保存源分组节点；外层循环逐个在公共位置建立同名分组，复制有显式配置值的属性，并把“过滤哪些分组”的关系重新指向公共位置。

接着处理每个分组包含的碰撞形状。includes 是源形状路径集合；suffixes 保存去掉 source_robot 前缀后的相对后缀。代码先验证每个源形状都在源机器人内，再截取后缀，避免把其他场景对象错误扩展成每个机器人的形状。

双层列表推导式把每个后缀接到每个 `env_path + '/Robot'` 后面，形成所有克隆实例的形状集合。比如源路径末尾为 `/LB_link/collision`，同一后缀会分别挂到 env_0、env_1 等机器人路径下。它扩展的是分组成员路径，不是为不同任务组设不同碰撞规则。

最后 `source.SetActive(False)` 停用源机器人子树内旧的过滤节点，后续使用刚建立的公共分组。地面没有被加入这些机器人内部过滤分组，因此保持地面接触。函数通过修改 stage 产生结果，正常返回 None。

其中 USD 的节点查询、属性复制、关系写入分别只负责“找节点、复制已有属性、写入路径集合”；阅读主线不需要展开这些库 API 的实现。返回 `_setup_scene()` 后继续完成同一个物理场景的构建。

### 3.3 用具体下标核对“动作列”和“机器人关节列”

这里需要先区分两个数量：当前机器人有 **6 个驱动关节**，而当前仿真资产的 `Articulation.joint_names` 实际包含 **14 项**。后者还列出了被动连杆关节和闭链闭合关节，不能把它理解成 14 个电机，也不能直接当作闭链机构的独立自由度数量。

这个 14 来自运行时实际返回的关节列表，不是根据六维动作推算的。环境在 [wheel_legged_vmc_flat_env.py:117](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py#L117) 打印 `self._robot.joint_names`。当前资产的实际顺序如下，表中下标从 0 开始：

| 关节类别 | Articulation 下标 | 实际名称 | 数量 |
| --- | --- | --- | --- |
| 腿部主动关节 | 0、1、2、3 | `LB_joint`、`LL_joint`、`RB_joint`、`RL_joint` | 4 |
| 被动连杆关节 | 4、5、6、7、8、9 | `LL1_joint`、`RL1_joint`、`LL2_joint`、`RL2_joint`、`LL3_joint`、`RL3_joint` | 6 |
| 闭链闭合关节 | 10、11 | `LL3_LS_closure`、`RL3_RS_closure` | 2 |
| 轮关节 | 12、13 | `LW_joint`、`RW_joint` | 2 |

因此，当前关节列表的长度是 `4 + 6 + 2 + 2 = 14`，策略控制的关节仍然只有 `4 + 2 = 6` 个。中间的 8 个被动或闭链关节没有各自对应的策略动作列。

两轮在当前完整关节张量中的下标确实是 12、13；六维动作中它们的下标则是 2、5。将来更换资产时，应重新读取实际关节列表，不能把这组资产下标直接写死在控制代码中。

因此读取动作时写 `_actions[:,(2,5)]`；读取机器人轮速时写 `joint_vel[:,self._wheel_joint_ids]`。前一个是策略坐标中的列，后一个是物理资产中的列，不能互换。

同样，`_torque_joint_ids` 不是简单的 `range(6)`。当前名称查找的实际结果是：

```text
六列 effort 的顺序：       [LB, LL, LW, RB, RL, RW]
对应 Articulation 下标：  [ 0,  1, 12,  2,  3, 13]
```

如果误用 `range(6)`，实际选择的就会是 `LB_joint`、`LL_joint`、`RB_joint`、`RL_joint`、`LL1_joint`、`RL1_joint`：两轮没有被选中，两个被动关节反而被选进来了。按名称构造 `_torque_joint_ids`，就是为了把六列 effort 写到正确的六个驱动关节上，而不是给全部 14 项关节都写入策略输出。

`preserve_order=True` 保住了请求列表中的业务顺序；紧接着比较 `resolved_legs`、`resolved_wheels` 等列表，是为了发现名字匹配虽然成功、顺序却与策略约定不同的情况。

### 3.4 正则、范数和 `.any()` 分别在哪个维度工作

`penalised_body_pattern` 可以匹配机身和多根腿部刚体。传感器因此返回多个 body ID，取出的接触力形状为 `[N,B,3]`，B 是匹配到的刚体数量。

`torch.norm(...,dim=-1)` 在最后的 xyz 维求合力大小，结果是 `[N,B]`。再执行 `.gt(threshold)` 得到每个刚体是否越阈值的布尔矩阵。

终止判断使用 `.any(dim=1)`，把“一台机器人有任意一根指定连杆发生持续不安全接触”归并成 `[N]`。奖励中的碰撞次数则可能在同一维求和，得到本环境本步有几个指定刚体超过阈值。

两者读取同一物理量，但输出意义不同：一个是失败逻辑的布尔条件，一个是用于计算代价的数量。它们也不能用轮子的正常支撑接触来替代。

```python
def _pre_physics_step(self, actions: torch.Tensor):
    # Episode events belong to this step only; a step without resets must
    # not repeat the previous step's ended episodes in RSL's rollout log.
    self.extras['log'] = {}
    # Preserve raw Gaussian outputs; leg targets keep their unit envelope.
    # A separately saved wheel clamp supplies transient reference headroom.
    self._raw_actions = torch.nan_to_num(
        actions, nan=0.0, posinf=1.0, neginf=-1.0
    )
    self._actions = torch.clamp(self._raw_actions, -1.0, 1.0)
    self._actions = apply_wheel_action_limit(
        self._actions, self._raw_actions, self.cfg.wheel_action_limit,
    )
```


### 6.1 为什么第一行先清空 `extras['log']`

`extras` 是传给 wrapper 和 runner 的附加信息字典。本环境的 `_reset_idx()` 会把刚刚结束的回合统计写到其中；如果下一步没有环境 reset，却继续留下上一步同一份 ended-episode 信息，runner 就可能把一次结束事件重复记入多次。

因此在每个新控制步开始时先把本步日志字典清空。这里不会清空 PPO 的 rollout，不会删除检查点，也不会把奖励归零。

后面的奖励与观测函数会重新填入本控制步的诊断，真正发生 reset 时再填入结束回合数据。日志生命周期与物理状态生命周期是两条不同的线。

### 6.2 `_raw_actions` 的 raw 到底到哪一层为止

`actions` 是 Actor 给出的 `[N,6]` 张量。`torch.nan_to_num` 先把 NaN、正无穷、负无穷换成指定有限值；有限但超过动作包络的值仍然保留。

所以 `_raw_actions` 更精确的定义是“已经做数值清洗、尚未做执行限幅的策略输出”。例如有限的 `1.3` 仍保存为 `1.3`，用于计算超出动作范围的代价，而 NaN 已经被换成 0。

这一点很重要：只看 `_raw_actions` 已经有限，不能证明 Actor 最初从未产生过 NaN。物理状态有限性和策略参数/原始推理输出的有限性，需要各自的诊断证据。

### 6.3 第一层 clamp 与后续关节角 clamp 怎样衔接

`torch.clamp(self._raw_actions,-1,1)` 得到初步执行动作。对普通有限输入，它只截取数值，不改变 N 行与六列的布局。

腿部随后还要经过 `joint_position_targets()`。该函数把归一化动作变成 rad，再与真实关节限位求交，因而第一层 ±1 限幅不能替代最终关节角限位。

原始动作保持为另一个张量，是为了让饱和惩罚仍能区分 `1.1` 和 `3.0`。如果只保留执行后的 1，这两个截断前完全不同的输出就会变得不可区分。

### 6.4 为什么轮子还要经过独立的 `apply_wheel_action_limit`

六维动作的腿列固定使用关节角映射包络。轮列可以使用检查点明确保存的轮速参考限幅，辅助函数只处理这两列。

当该限幅为 1 时，轮列与普通 ±1 执行包络一致。若一个明确记录的实验保存了更大轮速参考包络，辅助函数会从 `_raw_actions` 恢复允许范围内的轮列，而不会扩大四个腿关节的动作包络。

这个参数影响的是软件目标轮速，不等于提高电机允许力矩，也不等于把实物额定转速当成已验证的极限。后面仍有执行器的力矩边界和物理响应。

本函数每个控制步只运行一次。它没有进入四次物理子步循环，也没有在这里求五连杆、重力前馈或更新网络参数。

#### 6.4.1 带着两张动作表进入轮列限幅，再回到预处理

源码：[wheel_control.py](../../wheel_legged_gym_isaaclab/wheel_control.py#L14)，第 14～28 行。

```python
def apply_wheel_action_limit(applied, raw, limit):
    """Keep all four leg columns intact; limit only wheel columns 2 and 5.

    The unit limit returns the historical action tensor without extra arithmetic.
    The wider limit matches the frozen wheel-reference intervention exactly.
    Neither the scale nor a motor's physical speed/torque limit changes here.
    """
    limit = validated_wheel_action_limit(limit)
    if applied.shape != raw.shape or raw.ndim != 2 or raw.shape[-1] != 6:
        raise ValueError('Expected paired six-dimensional action tensors')
    if limit == 1.:
        return applied
    result = applied.clone()
    result[:, (2, 5)] = raw[:, (2, 5)].clamp(-limit, limit)
    return result
```

`applied` 是已经逐元素裁到 ±1 的 `[N,6]`，`raw` 是数值清洗后、尚未执行裁剪的 `[N,6]`。函数先复用构造阶段讲过的 `validated_wheel_action_limit()`，再确认两张表形状相同且每行六列。

`limit==1` 时直接返回传进来的 `applied` 对象，既没有再做一次乘法，也没有创建额外副本。大于 1 时先 `clone()`，然后只把第 2、5 列从 raw 中取出并裁到 `[-limit,limit]`。四个腿列完整保留，不能因为轮动作包络变宽就同时把腿关节包络扩大。

例如教学输入中某个轮 raw=1.2，通用 clamp 后先变成 1；若保存的轮上限为 1.25，这个函数允许恢复到 1.2；raw=1.8 则只恢复到 1.25。构造阶段的检查保证它不会接收任意大的上限。函数返回的仍是归一化动作，乘 `action_scale_vel` 变成 rad/s 是后面的执行步骤。

回到 `_pre_physics_step()`，返回值重新赋给 `_actions`。本函数不改 `_raw_actions`，所以后面仍能从 raw 计算超范围代价。它每控制步运行一次；接着基类才进入多个物理子步，调用下一节的 `_apply_action()`。

```python
def _update_forward_kinematics(self, env_ids: torch.Tensor | None = None):
    """Mapped large five-bar state, Jacobian and analytic virtual velocity."""
    dof_pos = self._robot.data.joint_pos
    dof_vel = self._robot.data.joint_vel
    if env_ids is not None:
        dof_pos = dof_pos[env_ids]
        dof_vel = dof_vel[env_ids]
    q_b = dof_pos[:, self._leg_joint_ids[::2]]
    q_l = dof_pos[:, self._leg_joint_ids[1::2]]

```

`joint_pos/joint_vel` 是 Articulation 的实际状态缓存。`env_ids=None` 表示全 N 台；给定部分 ID 时，先抽出 K 台的行。`_leg_joint_ids[::2]` 取左右 B 类主动关节，`[1::2]` 取左右 L 类，得到两张 `[批次,2]` 的角度表。

下一行第一次进入张量版 `five_bar_state(q_b,q_l,**geometry)`。`**` 将几何字典拆成具名参数 `upper/lower/offsets/scale/branch`，不增加张量维度。构造阶段的 `_points()` 处理一套名义姿态；这里用张量同时处理所有环境和左右两腿。

源码：[five_bar_vmc.py](../../wheel_legged_gym_isaaclab/five_bar_vmc.py#L5)，第 5～26 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/five_bar_vmc.py:5:26 -->

```python
def five_bar_state(q_b, q_l, *, upper, lower, offsets, scale, branch):
    """Return length, backward-positive leg angle, raw-motor Jacobian, validity.

    Inputs [..., 2] use leg order [left, right], radians at the exported zero.
    J[..., 0, :] = d(length)/d(q_B,q_L), J[..., 1, :] = d(angle)/d(q_B,q_L).
    Standard base axes are X forward, Y left, Z up; theta=atan2(-X,-Z).
    """
    sign = q_b.new_tensor([1., -1.])
    theta_b = offsets[0]+sign*q_b
    theta_l = offsets[1]+sign*q_l
    c = upper[0]*torch.stack((theta_b.cos(),theta_b.sin()),dim=-1)
    a = upper[1]*torch.stack((theta_l.cos(),theta_l.sin()),dim=-1)
    delta = a-c
    distance = torch.linalg.vector_norm(delta,dim=-1)
    d = distance.clamp_min(1e-7)
    along = (lower[0]**2-lower[1]**2+d.square())/(2*d)
    height2 = lower[0]**2-along.square()
    normal = torch.stack((-delta[...,1],delta[...,0]),dim=-1)/d[...,None]
    p = c+along[...,None]*delta/d[...,None]+branch*height2.clamp_min(0).sqrt()[...,None]*normal
    wheel = scale*p  # CAD (Y,Z), i.e. standard (Z,X), relative to hip
    length = torch.linalg.vector_norm(wheel,dim=-1).clamp_min(1e-6)
    angle = torch.atan2(-wheel[...,1],-wheel[...,0])
```

这一段得到几何末端、腿长和摆角，还没结束函数。下面沿同一段计算把维度、装配分支、数值保护和后半段 Jacobian 一起读完，再回到调用方使用四个返回值。

#### 7.1.2 先把五连杆的每个输入、输出维度列清楚

| 变量 | 一般形状 | 最后几维的含义 |
| --- | --- | --- |
| `q_b`, `q_l` | `[N,2]` | 每环境左、右腿同类主动角 |
| `a`, `c`, `p`, `wheel` | `[N,2,2]` | 环境、腿、平面坐标 |
| `length`, `angle`, `valid` | `[N,2]` | 环境、腿 |
| `jacobian` | `[N,2,2,2]` | 环境、腿、虚拟坐标、主动关节 |
| `velocity` | `[N,2,2]` | 环境、腿、两个主动关节速度 |
| `virtual_velocity` | `[N,2,2]` | 环境、腿、`L_dot/theta_dot` |

两个长度为 2 的维度不能因为数值相同而互换。特别是 Jacobian 的第一个“2”是左右腿，而最后两个“2”构成每条腿自己的 2×2 矩阵。

`five_bar_state(...,*,upper,lower,offsets,scale,branch)` 中的 `*` 表示后续参数必须按关键字传入。环境用 `**cfg.five_bar_geometry` 展开字典，使字典键与这些参数名一一对应。

#### 7.1.3 `sign` 和 `offsets` 为何必须在求导前处理

原始左右电机坐标采用镜像轴约定。`sign=[1,-1]` 在 `[N,2]` 的腿维广播，使右腿主动角先换成同一几何平面的方向，再计算杆端位置。

`offsets[0]` 与 `offsets[1]` 是五连杆几何采用的两类 CAD 零位偏置。它们不等于策略的四个 `leg_joint_position_offset`：前者把实际原始角转换成几何杆角，后者把归一化动作转换成目标原始角。

求导时 `dc`、`da` 又包含同一个 `sign`，是因为 `d(theta)/d(q)` 本来就带左右轴符号。这样得到的 Jacobian 已经相对于原始电机坐标求导。后面用 `J^T` 映射腿力时，不应再凭直觉额外对右腿力矩整体取反。

#### 7.1.4 `a`、`c`、`delta` 与两圆交点逐项推导

`c` 和 `a` 是两条上杆末端的平面坐标。例如 `torch.stack((cos(theta_b),sin(theta_b)),dim=-1)` 把两个 `[N,2]` 标量场拼成 `[N,2,2]` 的单位方向，再乘上杆长。

`delta=a-c` 是两个圆心之间的向量，`distance=norm(delta)` 是圆心距。末端 `p` 同时到 c 的距离为 `lower[0]`、到 a 的距离为 `lower[1]`，因此它是两个定半径圆的交点。

把沿 `c→a` 方向的投影距离记为 `s`，交点垂直该方向的高度记为 `h`，由两条距离约束相减可以得到：

```text
s = (lower[0]^2 - lower[1]^2 + d^2) / (2d)
h^2 = lower[0]^2 - s^2
p = c + s×(delta/d) + branch×sqrt(h^2)×normal
```

源码中的 `along` 对应 s，`height2` 对应 h²。`normal=(-delta_y,delta_x)/d` 把圆心方向旋转九十度，并保持单位长度。

`branch` 选择垂线两侧的装配解。同一组电机角，数学上可能对应两个交点；当前装配规定的分支必须与资产实际机构一致。不能在训练过程中为了让一个目标“看起来更容易达到”随意换另一支解。

#### 7.1.5 为什么 clamp 后还能返回 `valid=False`

当圆心距极小，直接除以 d 会数值发散；当 h² 因机构不可达或误差成为负数，直接开平方会产生 NaN。代码用 `clamp_min` 先保证接下来得到有限的中间值。

但有限中间值不代表该机构状态真实有效。源码另外用原始 `distance`、未截断的 `height2` 和行列式检查 `valid`。

因此要同时保留两条信息：数值保护让后续张量计算有定义；`valid` 把无效几何或接近奇异的事实继续交给终止/诊断。只保留前者并丢掉后者，会把一个被数值保护遮住的错误几何误当成正常状态。

`wheel=scale*p` 把求出的等效末端换到轮端长度。项目的 `mapped_five_bar_geometry()` 已经把长度尺度乘到上下杆，并把传给运行时的 `scale` 设为 1；这避免同一比例在运行时再乘第二次。

#### 7.1.6 Cartesian Jacobian 为什么长成源码那样

源码：[five_bar_vmc.py](../../wheel_legged_gym_isaaclab/five_bar_vmc.py#L27)，第 27～41 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/five_bar_vmc.py:27:41 -->

```python
u,v = p-c,p-a
dc = sign[...,None]*upper[0]*torch.stack((-theta_b.sin(),theta_b.cos()),dim=-1)
da = sign[...,None]*upper[1]*torch.stack((-theta_l.sin(),theta_l.cos()),dim=-1)
rhs_b=(u*dc).sum(-1)
rhs_l=(v*da).sum(-1)
determinant=u[...,0]*v[...,1]-u[...,1]*v[...,0]
valid=(distance>1e-5)&(height2>1e-10)&(determinant.abs()>1e-7)
det=torch.where(determinant<0,-determinant.abs().clamp_min(1e-7),determinant.abs().clamp_min(1e-7))
j_cart=scale*torch.stack((
    torch.stack((v[...,1]*rhs_b,-u[...,1]*rhs_l),dim=-1),
    torch.stack((-v[...,0]*rhs_b,u[...,0]*rhs_l),dim=-1)),dim=-2)/det[...,None,None]
polar=torch.stack((wheel/length[...,None],
                   torch.stack((-wheel[...,1],wheel[...,0]),dim=-1)/length.square()[...,None]),dim=-2)
jacobian=polar@j_cart
return length,angle,jacobian,valid
```


先设 `u=p-c`、`v=p-a`。两根下杆的长度不变，因此有 `u·u=lower[0]^2`、`v·v=lower[1]^2`。

对约束求微分，得到 `u^T dp=u^T dc`、`v^T dp=v^T da`。当只改变 B 类关节时，右端第二项为零；当只改变 L 类关节时，第一项为零。这正是 `rhs_b=(u*dc).sum(-1)` 与 `rhs_l=(v*da).sum(-1)` 的来源。

把两条约束写成矩阵：

```text
M = [[u_x, u_y],
     [v_x, v_y]]

M × dp = [rhs_b×dq_B, rhs_l×dq_L]^T
det(M) = u_x×v_y - u_y×v_x
```

求 `M` 的逆并乘上右端，就得到 `j_cart` 中的四个分子。它不是凭经验给左右电机分配力矩，而是约束求导得到的末端位置对原始电机角的导数。

`det` 的保护保留原行列式符号。若把所有很小的负分母都粗暴截成正数，导数方向可能被翻转；源码通过 `where` 分正负处理，目的是避免这种符号破坏，同时仍通过 `valid` 标记奇异风险。

#### 7.1.7 从末端坐标导数，变成腿长和腿角导数

`j_cart` 的输出坐标还是平面位置。最终需要的是 `[L,theta]`，所以还要乘 `polar`。

长度 `L=sqrt(w0²+w1²)` 对末端向量的导数是 `[w0,w1]/L`，对应 `polar` 的第一行。

角度定义为 `atan2(-w1,-w0)`，其微分为 `(-w1×dw0+w0×dw1)/L²`，对应第二行 `[-w1,w0]/L²`。使用 `atan2` 可以区分象限，不能直接换成只看比值的 `atan`。

链式法则因此是：`J_virtual = J_polar @ J_cart`。代码的 `@` 在最后两个矩阵维执行乘法，前面的 N 和左右腿维按批次匹配。

第一行单位近似为 m/rad，第二行是 rad/rad。由它计算 `J*q_dot`，第一项就是 m/s，第二项就是 rad/s，和 `_L0_dot`、`_theta0_dot` 的物理含义一致。

#### 7.1.8 `[...,None]`、`squeeze(-1)` 和部分重置的写回

`velocity` 是 `[N,2,2]`。`velocity[...,None]` 在最后加一维，变成 `[N,2,2,1]` 的列向量；与 `[N,2,2,2]` 的 Jacobian 相乘后得到 `[N,2,2,1]`。

`.squeeze(-1)` 只删掉最后那一维长度 1，结果恢复 `[N,2,2]`。如果不指定维度，在 N=1 的教学/回放环境中还可能意外删掉环境维，造成只在小批量调试时出现的形状错误。

`selection = slice(None) if env_ids is None else env_ids` 统一了全量和部分更新：普通物理子步更新全部 N 行；只重置 K 台机器人时，输入先选 K 行，计算结果也只写回这 K 行。

这种写法让没有 reset 的其他机器人继续保留自己的状态缓存。它不是先把全部缓存清零，再把少数重置环境补回来。

源码：[wheel_legged_vmc_flat_env.py](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py)，第 411 至 420 行。

`joint_position_targets()` 的完整函数体、广播、交集限位和 `validate` 分支已经在[构造函数的首次调用处](#first-call-joint-position-targets)逐段展开。现在继续读 `_apply_direct_joint_position_action()`，要比较的是两次调用如何使用同一个函数：

## 八 关节目标怎样进入 PhysX

### 8.1 set target 先写缓存

`Articulation.set_joint_position_target()` 位于 [articulation.py](../../../IsaacLab/source/isaaclab/isaaclab/assets/articulation/articulation.py)。它把目标写入内部 `joint_pos_target` 缓存，速度和 effort 接口也有各自缓存。

后续调用链为：

```text
环境设置 position / velocity / effort target
    → scene.write_data_to_sim()
    → Articulation.write_data_to_sim()
    → _apply_actuator_model()
    → 物理接口写入关节目标与前馈
    → sim.step() 求解实际运动
```

这也是为什么重置“写实际状态”和“清旧目标”必须分别处理。前者改变当前 q、dq，后者防止下一步继续追踪旧回合的目标。

### 8.2 隐式 PD 的公式该怎样理解

在概念上，可以写成：

```text
tau_PD ≈ Kp × (q_target − q)
       + Kd × (dq_target − dq)
tau_total ≈ tau_PD + tau_feedforward
```

但当前执行由 PhysX 在离散物理求解中处理，不能把这条连续形式近似公式当成每次内部求解得到的精确实测力矩。

Isaac Lab 的 [ImplicitActuator.compute](../../../IsaacLab/source/isaaclab/isaaclab/actuators/actuator_pd.py) 会根据这个形式生成用于遥测和奖励的近似力矩，再返回原控制目标。它不是把整个执行切换成 Python 显式 PD。

因此 `applied_torque` 的解释要考虑隐式执行器的估计属性。只看 `_leg_gravity_effort_applied`，则连 PD 部分都没有包括。

### 8.3 缓存 setter 已经返回，此时物理还没有推进

位置和速度 setter 的索引、数据形状及缓存写入已在[首次提交关节目标的位置](#first-call-joint-target-setters)展开。这里接着解释：setter 完成的是引用目标的提交准备，实际求解要等场景统一写入和 `sim.step()`。

### 8.6 三种“清零”会产生三种结果

```python
def gravity_feedforward(leg_angle, body_pitch, *, mode, force, angle_bias=0.0,
                        force_limit=GRAVITY_FORCE_LIMIT):
    """Outward-positive radial force [N], with no gas-spring contribution.

    The configured base force is half the nominal whole-vehicle weight.
    MCU angle compensation converts that vertical support into radial force;
    it does not change the mass definition or impose equal instantaneous loads.

    leg_angle is backward-positive relative to base_link; body_pitch uses the
    simulation Y-axis convention. Their sum corresponds to MCU theta0 after
    encoder/frame conversion. MCU F0 is inward-positive, hence F_sim = -F0.
    The near-zero cosine guard keeps the MCU +/-150 N cap finite at singularity.
    """
    import torch
    if not math.isfinite(force) or force < 0:
        raise ValueError("Gravity force must be nonnegative and finite")
    if mode == "constant":
        return torch.full_like(leg_angle, force)
    if mode != "mcu_pitch_compensated":
        raise ValueError(f"Unknown gravity feedforward mode: {mode}")
    if not math.isfinite(force_limit) or force_limit <= 0 or not math.isfinite(angle_bias):
        raise ValueError("Gravity compensation needs a positive cap and finite angle bias")
    angle = leg_angle + body_pitch + angle_bias
    # Reproduce the wrap and sign check of get_l_theta / F0_control.
    angle = torch.where(angle > 1.1, angle - 2 * math.pi, angle)
    cosine = angle.cos()
    denominator = torch.where(cosine < 0, -cosine.abs().clamp_min(1e-6),
                              cosine.abs().clamp_min(1e-6))
    result = (force / denominator).clamp(-force_limit, force_limit)
    return torch.where(angle > math.pi / 2, -result, result)
```

这段属于项目应用代码：它定义本机器人采用哪种重力前馈、角度和力的符号怎样转换、何时限幅，需要顺着分支读。这里用到的 `full_like`、`where` 和 `clamp` 只按其张量作用理解，不进入 PyTorch 实现。

| 输入 | 来源与含义 |
| --- | --- |
| `leg_angle` | `_theta0`，形状 `[N,2]`，左右腿相对机身的摆角，单位 rad。 |
| `body_pitch` | 上一层由投影重力求出的 `[N,1]` 机身倾角；相加时广播到两条腿。 |
| `mode` | 本次训练统一使用的前馈模式字符串，不随某个高度或速度切换。 |
| `force` | 每条腿的名义竖直支撑力，单位 N，取名义整车重力的一半。 |
| `angle_bias` | 标量角度偏置，单位 rad，参与坐标补偿。 |
| `force_limit` | 径向前馈力的正上限，单位 N；它与后面电机力矩的 N·m 限幅不同。 |

函数先检查 `force` 有限且非负。若选择 `constant`，立即返回与 `leg_angle` 同形状、同设备的常量力张量。注意这个分支提前返回，因此不会走后面的角度补偿或 `force_limit` 检查。它也没有在内部计算质量或乘重力加速度；传入的 `force` 已经是力。

剩余分支只接受 `mcu_pitch_compensated`。模式未知就报错；进入该模式后，还要检查力上限为有限正值、角度偏置有限。这些判断在整个批次上使用同一份配置，避免一个错误标量传播到所有环境。

`angle=leg_angle+body_pitch+angle_bias` 得到 `[N,2]` 的补偿角。相对机身腿角只在这里叠加一次机身 pitch。随后 `where(angle > 1.1, angle - 2π, angle)` 按下位机约定选择角度表示；这里的 1.1 是既有坐标转换规则，不是根据验收失败工况新增的控制分支，也不等同于通用的 `wrap_to_pi()`。

`cosine` 保存每条腿补偿角的余弦。`denominator` 保留余弦的正负号，同时把绝对值下限设为 `1e-6`，避免恰好除零。`result` 再计算径向力并裁剪到 `[-force_limit, force_limit]`。正常姿态下可近似理解为 `F_base/cos(angle)`：把竖直支撑需求换算成虚拟腿径向力，并没有改变名义质量。

最后一行按照补偿后的角度处理力方向，返回 `[N,2]` 的径向力，约定向外为正。近零分母保护保证计算有限，力限幅保证输出有界；两者作用不同，不能只保留其中一个。

返回顺序是 `gravity_feedforward()` → `_get_gravity_feedforward()` → 当前 `five_bar_torques()` 的 `force` 参数。这个返回值还是 N，还没有写入机器人，也不是最终的四个电机力矩。接着读下一步的 Jacobian 转置映射。

### 9.3 Jacobian 转置把力映射为电机力矩

源码：[five_bar_vmc.py](../../wheel_legged_gym_isaaclab/five_bar_vmc.py)，第 44 至 47 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/five_bar_vmc.py:44:47 -->

```python
def five_bar_torques(jacobian, force, torque):
    """Virtual work in raw motor coordinates, including each side's axis sign."""
    effort=jacobian.transpose(-1,-2)@torch.stack((force,torque),dim=-1)[...,None]
    return effort[...,0,0],effort[...,1,0]
```

依据虚功关系，虚拟坐标力 `[F,T]` 与关节力矩满足：

```text
tau = J(q)^T × [F, T]^T
```

输入 `jacobian` 是前面正运动学保存的 `[N,2,2,2]` 张量：四个轴依次是环境、左右腿、虚拟坐标 `[腿长,摆角]`、主动电机 `[B,L]`。`force` 与 `torque` 均为 `[N,2]`，分别是径向力 N 和绕虚拟腿坐标的力矩 N·m。两者对应不同物理量，不能当作两个电机的力矩。

`stack((force,torque),dim=-1)` 在最后增加虚拟力分量轴，得到 `[N,2,2]`；接着 `[...,None]` 变成 `[N,2,2,1]` 的列向量。`transpose(-1,-2)` 只交换 Jacobian 的最后两轴，保留环境和左右腿两轴，所以矩阵乘法会分别计算每台机器人的每条腿。

乘法结果 `effort` 为 `[N,2,2,1]`，倒数第二轴现在是主动电机轴。返回的 `effort[...,0,0]`、`effort[...,1,0]` 各为 `[N,2]`：`t1` 保存左右两条腿的 B 电机力矩，`t2` 保存左右两条腿的 L 电机力矩。它们不是“左腿一对”和“右腿一对”。原始电机轴符号已经包含在 Jacobian 中，这里不再补乘一次左右符号。

当前调用给 `torque` 传入 `zeros_like(self._theta0)`，即零虚拟摆角力矩；`force` 是刚返回的重力径向力。因此这次只产生重力前馈，函数内部没有关节角误差、腿长误差或 PID 状态。它虽然使用 VMC 的虚功映射数学关系，也没有把 Actor 的直接关节角目标改成另一套 VMC 反馈。

返回调用处后，`stack((t1[:,0],t2[:,0],t1[:,1],t2[:,1]),dim=-1)` 才把结果排成四列 `[LB,LL,RB,RL]`。四列随后进入前馈力矩限幅和六列 effort 组装，目标角仍沿前面的独立位置通道提交。

```python
def _get_wheel_vel_forward_positive(self) -> torch.Tensor:
    """Return wheel speeds with positive values meaning forward motion.

    The mirrored URDF hip frames make the raw right-wheel joint axis point
    opposite to the raw left-wheel joint axis. Canonicalizing the right
    coordinate here gives the policy one consistent wheel convention.
    """
    wheel_vel_raw = self._robot.data.joint_vel[:, self._wheel_joint_ids]
    return torch.stack(
        (wheel_vel_raw[:, 0], -wheel_vel_raw[:, 1]), dim=1
    )
```

读取时左轮保持原符号、右轮取反。这样策略和诊断中的两个轮速都使用“正值向前”的共同约定。

### 9.5 从虚功看 `J^T`，以及为什么 T=0 仍有两个关节力矩

虚拟坐标满足 `dx=J*dq`。若虚拟坐标力为 `f=[F,T]^T`，虚功相等要求 `tau^T*dq=f^T*dx=f^T*J*dq`，所以 `tau=J^T*f`。

直接模式给的是径向重力力 F、虚拟摆角力矩 T=0。此时两个电机仍分别承担 `dL/dq_B×F`、`dL/dq_L×F`，所以 T=0 不代表其中一个髋电机前馈必然为零。

`torch.stack((force,torque),dim=-1)[...,None]` 把两个 `[N,2]` 量组成 `[N,2,2,1]`。返回的 `t1` 和 `t2` 各为 `[N,2]`，列顺序仍是左腿、右腿。

环境再使用 `stack((t1[:,0],t2[:,0],t1[:,1],t2[:,1]),dim=-1)` 组装成 `[LB,LL,RB,RL]` 四列。少看这一层重新排布，很容易误以为 `t1` 已经直接等于左腿两个电机。

### 9.6 重力补偿里 `[:,None]` 的广播与实际受力含义

机身 pitch 原始形状为 `[N]`，`[:,None]` 把它变成 `[N,1]`；腿摆角为 `[N,2]`，相加时同一环境的一个机身倾角便广播到左右两条腿。

如果不增加这一维，`[N]` 与 `[N,2]` 的最后一维通常无法匹配。尤其 N 恰好为 2 时，错误写法还可能运行却把环境维当成腿维，产生很难从形状表面发现的错误。

本项名义 F 是整车名义重力的一半。除以补偿角余弦，是把竖直支撑需求换成沿虚拟腿方向的径向力；这个名义前馈约定并不要求运动中两轮接触力始终严格相等。

余弦接近零时，源码先保留符号并限制分母，再限制 F 的绝对值。其角度折返和最后的符号判断来自下位机坐标约定。不能只摘出一个 `force/cos(angle)`，就省掉其余保护与坐标说明。

```python
@staticmethod
def _sanitize_observation(value: torch.Tensor, limit: float) -> torch.Tensor:
    """Replace non-finite values and clip one physical observation block."""
    return torch.clamp(
        torch.nan_to_num(value, nan=0.0, posinf=limit, neginf=-limit),
        min=-limit,
        max=limit,
    )
```

`@staticmethod` 表明它不读取 `self`，只处理传入的一个观测块。`value` 可以是 `[N,3]` 的陀螺仪，也可以是 `[N,4]` 的关节状态；`limit` 是这一类物理量自己的标量边界，不是整份 27 维观测统一采用一个单位。

`nan_to_num` 把 NaN 替换为 0，正负无穷替换为相应正负 limit；再用 `clamp` 裁有限的大值。两次都是非下划线版本，不把机器人原始状态缓存原地改掉。返回的张量形状和输入相同，后面的乘尺度也不会改变行列布局。

以教学值角速度 8 rad/s、limit=5、scale=0.25 为例，先裁到 5，再输入 1.25。若颠倒顺序，8 先变成 2 而不再触发 limit=5，含义完全不同。清洗只是让 Actor 输入有界，原始物理状态数值异常仍须由失败判断与诊断发现。

返回 `torch.cat`，调用方接着乘 `obs_scales.ang_vel`。投影重力则仅清洗而不再乘角速度尺度。等读到腿部块里的同名清洗调用时，用的仍是这个函数，只是输入和 limit 换成了对应关节量。

### 11.3 为什么水平速度不用简单的机体系前两列

源码：[wheel_legged_vmc_flat_env.py](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py)，第 593 至 618 行。

```python
def _get_heading_frame_horizontal_velocity(self) -> torch.Tensor:
    """Return horizontal velocity in the yaw-aligned heading frame.

    Unlike ``root_lin_vel_b[:, :2]``, this projection is independent of
    body roll and pitch. The policy therefore cannot change its measured
    forward speed merely by leaning the chassis.
    """
    forward_axis_b = torch.zeros(self.num_envs, 3, device=self.device)
    forward_axis_b[:, 0] = 1.0
    forward_axis_w = quat_apply(self._robot.data.root_quat_w, forward_axis_b)
    heading_forward = forward_axis_w[:, :2]
    heading_forward = heading_forward / torch.clamp(
        torch.linalg.vector_norm(heading_forward, dim=1, keepdim=True),
        min=1.0e-6,
    )
    heading_left = torch.stack(
        (-heading_forward[:, 1], heading_forward[:, 0]), dim=1
    )
    velocity_xy_w = self._robot.data.root_lin_vel_w[:, :2]
    return torch.stack(
        (
            torch.sum(velocity_xy_w * heading_forward, dim=1),
            torch.sum(velocity_xy_w * heading_left, dim=1),
        ),
        dim=1,
    )
```

函数先把机身前向轴转到世界系，再投影到水平面并归一化。随后构造水平左向轴，将世界水平速度投影到这两个轴。

这样前向速度随 yaw 航向转动，但不会仅因机身 pitch、roll 改变就改变速度定义。否则策略可能通过倾斜机身改变“机体系速度数值”，而不是真正改变地面上的前进速度。

### 11.4 历史动作在什么时候更新

`_get_observations()` 在返回前，把上一控制步动作向后移动，再保存刚刚执行的动作。下一次 Actor 推理看到的是前一次执行信息。

奖励计算发生在这个历史更新之前，因此 `action_rate` 比较的是当前动作与此前动作，而不是与刚刚复制的自身比较。

这类时序不能仅靠变量名判断，必须结合基类 step 调用顺序。

### 11.5 用三帧时间线检查动作历史有没有错一拍

采用 RL 常用下标：Actor 在 `obs_t` 上生成 `a_t`。进入该步以前，任务缓存 `_actions` 中还是上一次的 `a_(t-1)`，两帧历史分别是 `a_(t-1)`、`a_(t-2)`。

| 时刻 | `_actions` | `_last_actions[:,:,0]` | `_last_actions[:,:,1]` |
| --- | --- | --- | --- |
| 收到本步 Actor 动作前 | `a_(t-1)` | `a_(t-1)` | `a_(t-2)` |
| 本步 `_pre_physics_step` 与目标限幅后 | `a_t` 的有效参考 | `a_(t-1)` | `a_(t-2)` |
| 本步 `_get_rewards` | 用当前与两帧旧参考计算变化代价 | 保持旧值 | 保持旧值 |
| 本步 `_get_observations` 更新历史后 | `a_t` | `a_t` | `a_(t-1)` |

因此动作速率惩罚读取的是 `a_t-a_(t-1)`，二阶变化惩罚读取的是 `a_t-2a_(t-1)+a_(t-2)`。如果把历史更新提前到奖励之前，第一个差值就可能变成零。

这里写入下一帧观测末尾的是 `_actions`，即已经完成本步参考映射的 `a_t`。网络在 `obs_(t+1)` 中看到自己刚刚给出的有效动作，并不会看到未来尚未生成的 `a_(t+1)`。

### 11.6 本任务的 `_get_observations()` 具有副作用

这里的“副作用”，是指函数除了返回 `{"policy": obs}`，还会修改环境中已经保存的变量。因此，即使物理状态完全没有变化，连续调用两次，也不能把它理解成“把同一张观测表读两遍”。

先回到本工程的应用层函数：[wheel_legged_vmc_flat_env.py](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py#L495)。需要关注的是以下两组写操作。

```python
self._update_commands()
max_command_step = self.cfg.commands.linear_acceleration_limit * self.step_dt
self._commands[:, 0] += torch.clamp(
    self._target_lin_vel_x - self._commands[:, 0],
    min=-max_command_step,
    max=max_command_step,
)

# 下方还有动作历史更新。
self._last_actions[:, :, 1] = self._last_actions[:, :, 0]
self._last_actions[:, :, 0] = self._actions[:]
```

#### 11.6.1 命令目标与当前命令为什么要分开

`_target_lin_vel_x` 保存采样得到的最终线速度目标；`_commands[:, 0]` 保存当前真正送入观测、用于本步跟踪的线速度参考。假设前者已经是 `0.8 m/s`，后者仍是 `0 m/s`，就需要逐步接近，而不是立即跳到 `0.8 m/s`。

`max_command_step` 是每个控制步允许的最大参考变化量。当前配置为 `linear_acceleration_limit=0.8 m/s²`、`step_dt=0.02 s`，所以它等于 `0.016 m/s`。`torch.clamp()` 将“剩余目标差”限制在正负这个范围内，再原地累加到 `_commands[:, 0]`。

正常情况下，每个控制步在生成下一帧观测时执行一次，斜坡就对应所配置的加速度。如果在相同物理状态下额外调用一次，则这段代码仍会再执行一次。假设目标还没有到达，参考就可能从 `0` 变为 `0.016`，随后又变为 `0.032 m/s`。这个变化发生在命令缓存里；它不表示机器人真的行驶了，也不表示时间计数器前进了。

达到目标、目标差为零，或者该环境属于固定零速站立组时，这段累加可以是零。因此应当说“额外调用可能推进斜坡”，不能说每次调用必然改变所有环境的速度命令。

#### 11.6.2 `_update_commands()` 是否每次都重新抽样

继续看本工程的 [`_update_commands()`](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py#L629)。当前动态分组训练使用全局阶段：

```python
phase = self.common_step_counter // max(
    1, int(self.cfg.commands.resampling_time / self.step_dt)
)
if phase != self._last_grouped_command_phase:
    self._last_grouped_command_phase = phase
    self._resample_commands_for(torch.arange(self.num_envs, device=self.device))
```

`common_step_counter` 是已经执行的控制步数；`_last_grouped_command_phase` 记住上次抽样属于哪个阶段。当前每 `5 s` 重采样、控制周期 `0.02 s`，所以每 `250` 个控制步进入一个新阶段。同一阶段内再次读取观测，比较结果为假，不会仅因这次读取再次抽样。

但这个保护只包住“是否重采样”的逻辑。返回 `_get_observations()` 后，外面的线速度斜坡和动作历史赋值仍会执行。不能由“同一阶段不重采样”推导出“读取观测没有副作用”。

另外，未走上述分组分支时，代码按 `episode_length_buf % period == 0` 选择环境。这个分支没有对同一步重复查询去重；如果环境恰好停在重采样时刻，多次调用可能多次进入 `_resample_commands_for()`。后者会调用本工程 `env_commands.py` 中的 `resample_commands()`，改写这些环境的命令缓存，并记录 `_command_resample_step`。这项区别取决于训练配置，不能混为同一种行为。

#### 11.6.3 重复读取如何影响动作历史

`_actions` 是本步已经限幅的有效动作；`_last_actions[:, :, 0]` 和 `[:, :, 1]` 是用于变化代价的两帧历史。假设本步刚执行 `a_t=0.2`，此前两步分别为 `0.1`、`0.0`，则两次读取的结果如下。表中只取一个关节展示，实际缓存同时覆盖全部环境和六维动作。

| 操作 | `_actions` | 历史第 0 帧 | 历史第 1 帧 | 是否执行物理步 |
| --- | --- | --- | --- | --- |
| 本步奖励已算完，尚未生成新观测 | 0.2 | 0.1 | 0.0 | 本步物理过程已结束 |
| 正常生成一次新观测 | 0.2 | 0.2 | 0.1 | 否 |
| 为打印日志又额外读取一次 | 0.2 | 0.2 | 0.2 | 否 |

最后一次读取使更早的 `0.1` 丢失。假设下一步动作是 `0.3`，正确的二阶差分为 `0.3 - 2×0.2 + 0.1 = 0`，多读一次后却变为 `0.3 - 2×0.2 + 0.2 = 0.1`，平方项为 `0.01`。也就是说，打印日志所引起的额外调用，有可能改变下一步动作平滑惩罚。

影响还取决于插入的位置。如果额外读取发生在本步奖励之前，历史第 0 帧可能提前被当前动作覆盖，`action_rate` 本应计算的“当前减前次”就可能变为零。如果发生在正常观测生成之后，上表中最直接的影响则是第二帧历史丢失。不能脱离调用时刻笼统地说每一种奖励都会受到同样影响。

#### 11.6.4 正常训练是否每个控制步都会重复读取

核对当前安装的 RSL-RL 和 Isaac Lab 接口后，实际关系为：

```text
RslRlVecEnvWrapper 构造
    → env.reset()
    → 任务生成重置后的观测

OnPolicyRunner 构造
    → env.get_observations()          # 用于构造算法

runner.learn() 开始
    → env.get_observations()          # 取得 rollout 的初始观测

随后每个 rollout 控制步
    → PPO.act(obs_t)
    → env.step(a_t)
        → 预处理动作、执行物理子步
        → 计算本步奖励
        → 重置已结束的环境
        → _get_observations()         # 生成 obs_(t+1)
    → 把返回的 obs_(t+1) 交给下一步
```

这些库接口在这里需要理解其用途和数据流：wrapper 的 `get_observations()` 返回观测字典封装成的 `TensorDict`，但对本任务会直接调用应用层 `_get_observations()`，并非读取 `obs_buf`；runner 在构造和 `learn()` 起始各查询一次。正常 rollout 循环使用 `env.step()` 返回的新观测，没有在每一步再额外查询一次。

启动阶段的查询也不等于物理步。初始动作和动作历史在重置时都是零，所以启动查询中的历史赋值通常仍是零；线速度斜坡是否变化还要看当前目标、恢复课程时钟和分组状态。`learn()` 的 `init_at_random_ep_len=True` 还会随机化各环境的回合年龄，因此不能把几次启动查询简单等同于几个普通控制步。

当前 `TrainingObserver` 在 `_act(observations)` 中复制已经传入的观测，在奖励回调后复制命令、速度等状态，并核对 PPO storage。它没有为诊断调用 `_get_observations()` 或 wrapper 的 `get_observations()`。因此，这里确认了一个需要遵守的接口约定，但还不能据此认定“训练监测多读取观测”就是当前稳态偏航误差的来源。

#### 11.6.5 调试时如何取得数据

正常训练中，优先记录 `env.step()` 已经返回的 `obs`，或者在现有 Actor、奖励和 storage 观测点读取对应数据。需要跨步保留张量时，用 `detach().clone()` 保存快照，避免后续原地更新让“旧记录”跟着变化。

只想打印当前命令，可以直接读取 `_commands`、`_target_lin_vel_x`、`common_step_counter`；只想看动作历史，可以读取 `_actions` 和 `_last_actions`。这些读取不需要再次调用任务回调。`obs_buf` 可用于查看最近一次 `step()` 保存的观测，但构造、重置或人为写入仿真状态之后，要先确认它是否存在、是否对应当前状态。

若以后重构这个接口，应保证命令推进和历史更新每个控制步只发生一次，并覆盖全部重置、部分重置和恢复训练的时序。不能只把 `_update_commands()` 随意移到 `_pre_physics_step()`：当前 Actor 看到的命令与本步奖励使用的命令是对齐的，修改顺序时必须保持这种对应关系。

本节的 CPU 复现直接抽取当前应用层方法，确认同一步连续查询会推进斜坡并覆盖历史，同时确认当前分组抽样只触发一次。证据：[observation_query_audit.json](../../../mine_model/results/joint_pd_body_plus1p3kg_20261026/observation_query_audit_20261026/observation_query_audit.json)。复现没有启动物理仿真，也没有修改训练代码或执行 PPO 更新。

### 11.7 平面投影为什么先归一化，再构造左向量

`quat_apply(root_quat_w, [1,0,0])` 把机身前向轴旋转到世界坐标。取前两列就是其水平投影，机身俯仰时这个投影的长度通常不再为 1。

除以水平范数后，`heading_forward` 成为单位平面朝向。再用 `[-y,x]` 构造单位左向量，最后分别与世界水平速度做点积，得到航向系的前向和横向速度。

分母 `clamp_min(1e-6)` 避免机身前轴几乎竖直时出现零除。它保证数值可计算，并不证明这种姿态适合继续站立；姿态终止条件仍然另行处理。

该投影使用四元数旋转，不是把世界速度的 x 分量直接当作前进速度。因此机器人偏航以后，仍按自身水平朝向衡量前进/后退，而不会因为朝向世界 y 轴就把正常行驶记成纯横移。

```python
def merge_step_diagnostics(episode_log, diagnostics):
    """Publish a fresh log after resets without aliasing the cached scalars.

    DirectRLEnv resets after rewards and replaces its episode log. RSL-RL also
    converts log values into tensors in place, so a shared dictionary is unsafe.
    """
    return {**episode_log, **diagnostics}
```

输入 episode_log 是当前回合日志字典，diagnostics 是最近一次聚合的跟踪诊断字典。`{**episode_log, **diagnostics}` 创建新字典，先展开回合字段，再展开诊断字段；同名键以后者为准。调用方把返回值赋回 `self.extras['log']`。

这一项目逻辑解决的是日志生命周期：reset 路径会替换 extras['log']，随后 `_get_observations()` 需要把当步跟踪诊断补回去。复制字典避免直接改写传入字典本身；同名键以 diagnostics 提供的值为准。这里没有计算 reward，也没有将诊断值写进 Actor 观测。

## 十二 命令抽样为什么放在观测函数附近

### 12.1 在观测开头，进入命令更新与重采样包装函数

```python
def resample_commands(self, env_ids):
    env_ids = torch.as_tensor(env_ids, dtype=torch.long, device=self.device)
    if env_ids.numel() == 0:
        return
    previous_speed = self._commands[env_ids, 0].clone()

    lin_min = float(self._command_ranges[0, 0].item())
    lin_max = float(self._command_ranges[0, 1].item())

    # 固定速度范围用于回放；按原来的随机数顺序抽取 yaw 和高度。
    if lin_min == lin_max:
        rand = torch.rand(env_ids.numel(), 3, device=self.device)
        self._commands[env_ids, :3] = (
            self._command_ranges[:, 1] - self._command_ranges[:, 0]
        )[None, :] * rand + self._command_ranges[:, 0][None, :]
    else:
        step = float(self.common_step_counter)
        standing_steps = float(self.cfg.commands.standing_only_steps)
```

`torch.as_tensor(...,dtype=torch.long,device=self.device)` 统一索引类型和设备；空集返回避免对零个环境继续抽样。`previous_speed` 保存当前已应用速度，后面会恢复它，使新目标仍经过斜坡。

`lin_min==lin_max` 只是识别固定线速度范围。yaw 和高度是否固定仍要看各自范围：如果一行上下限相同，`(max-min)*rand+min` 自然恒定，否则仍随机。这个分支保留原随机数调用顺序，不使用下面的分组采样和 `training_motion_scale`；因此固定回放给出的物理命令不能再被悄悄乘一次训练阶段比例。

```python
def training_height_bounds(commands, center, step, motion_progress):
    """Expand only height from a saved range; never restart speed/yaw curricula."""
    final = tuple(commands.ranges_height)
    independent = getattr(commands, 'full_height_range_from_start', False)
    if not isinstance(independent, bool):
        raise ValueError('full_height_range_from_start must be boolean')
    if independent:
        if (len(final) != 2 or not all(math.isfinite(v) for v in final)
                or not 0 < final[0] <= center <= final[1]):
            raise ValueError('Full height range must be finite, positive and contain the nominal height')
        return final
    initial = getattr(commands, 'height_expansion_from', None)
    p = min(max(float(motion_progress), 0.), 1.)
    if initial is None:
        return tuple(center + (v - center) * p for v in final)
    if (len(initial) != 2 or not all(math.isfinite(v) for v in (*initial, *final))
            or not final[0] <= initial[0] <= center <= initial[1] <= final[1]):
        raise ValueError('Height expansion must start inside the final range and contain the nominal height')
    start = commands.height_expansion_start_steps
    duration = commands.height_expansion_ramp_steps
    if type(start) is not int or start < 0 or type(duration) is not int or duration <= 0:
        raise ValueError('Height expansion requires a nonnegative step and positive duration')
    expansion = min(max((float(step) - start) / duration, 0.), 1.)
    envelope = tuple(a + (b - a) * expansion for a, b in zip(initial, final))
    return tuple(center + (v - center) * p for v in envelope)
```

`commands` 是命令配置对象，`center` 是名义机身高度，`step` 是全局控制步，`motion_progress` 是刚算出的主运动课程进度。返回值是两个 Python 数值 `(low,high)`，不是每台机器人的高度命令张量。

先看 `full_height_range_from_start`：它必须是布尔值。为真时，检查最终区间有限、为正且包含中心，然后直接返回完整区间；这个早返回使高度范围不再随运动进度缩小。因此可以只让速度为零，同时训练完整高度范围，不能把所有课程都混为一个比例。

该开关为假、又没有 `height_expansion_from` 时，返回 `center+(端点-center)*p`：p=0 两端都等于中心，p=1 恢复最终范围。若设置了独立初始区间，则先验证它位于最终区间内部且包住中心，再按自己的 start/duration 把初始区间扩到最终区间，最后仍乘主进度 p。

两个 `min(max(...))` 都做标量夹取，但含义不同：p 来自运动课程，expansion 来自独立高度扩展时钟。函数只算抽样范围，不测量机身高度，也不输出关节目标；高度安全范围的几何来源和余量见第一篇。

```python
def sample_grouped_motion(env_ids, config, progress, reverse_progress, yaw_progress, phase=0,
                          *, dedicated_standing_count=None):
    """Sample assigned task roles using one shared policy and height curriculum."""
    groups = grouped_task_ids(env_ids, phase, dedicated_standing_count)
    count, device = env_ids.numel(), env_ids.device
    progress = min(max(float(progress), 0.), 1.)
    reverse_progress = min(max(float(reverse_progress), 0.), 1.)
    low, high = config.ranges_lin_vel_x
    vmax = low + (high - low) * progress
    reverse_low, reverse_high = config.ranges_reverse_lin_vel_x
    vmin = reverse_high + (reverse_low - reverse_high) * reverse_progress
    forward = low + (vmax - low) * torch.rand(count, device=device)
    reverse = vmin + (reverse_high - vmin) * torch.rand(count, device=device)
    boundary = torch.rand(count, device=device) < config.speed_boundary_fraction
    forward = torch.where(boundary, vmax, forward)
    reverse = torch.where(boundary, vmin, reverse)
    slow = torch.rand(count, device=device) < config.grouped_low_speed_fraction
    transition_low, transition_high = config.ranges_transition_lin_vel_x
    # Keep low-speed practice in the group's assigned direction, avoiding accidental zero commands.
    positive_max = transition_high * progress
    negative_max = -transition_low * reverse_progress
    positive_min, negative_min = min(.02, positive_max), min(.02, negative_max)
    forward_slow = positive_min + (positive_max - positive_min) * torch.rand(count, device=device)
    reverse_slow = -(negative_min + (negative_max - negative_min) * torch.rand(count, device=device))
    forward = torch.where(slow, forward_slow, forward)
    reverse = torch.where(slow, reverse_slow, reverse)
    speed = torch.zeros(count, device=device)
    speed = torch.where((groups == 2) | (groups == 4), forward, speed)
    speed = torch.where((groups == 3) | (groups == 5), reverse, speed)
    # Original startup curriculum is respected when training from scratch.
    enabled = torch.rand(count, device=device) < progress
    enabled &= ~(((groups == 3) | (groups == 5)) & (reverse_progress == 0.))
    speed = torch.where(enabled, speed, 0.)
```

函数先复用构造阶段已经展开的 [grouped_task_ids](#first-call-grouped-task-ids)，这次传入实际全局 ID 与全局 phase。返回的角色 0～5 决定是站立、原地转向、前进、倒车、前进转向还是倒车转向；它没有根据某个验收失败点写特定高度或特定速度分支。

`count/device` 来自当前 ID 批次，所有随机张量都是 `[count]`。主前进上端从配置下端随 progress 扩到上端；倒车下端从靠近零的 `reverse_high` 随 reverse_progress 扩到更负的 `reverse_low`。因此 progress 不仅是简单给现成速度乘比例，它也改变可抽取范围。

`boundary` 掩码把一部分前进/倒车样本放到相应极值。`slow` 掩码再选择低速练习：正向仍为正、反向仍为负，幅度从 `min(0.02,端点)` 到过渡区间端点。这个 0.02 是一般低速采样下界的保护，不是对某个测试工况的纠偏值；课程为零时该范围也退化为零。

随后按角色组装 speed。角色 2/4 取 forward，3/5 取 reverse，0/1 保持零。`enabled` 再按主进度决定是否启用，倒车进度尚为零时相应倒车组也保持零。专用站立组的速度不会因 phase 变化被启用。

```python
def sample_yaw_rates(count, *, device, low, high, fraction, minimum, boundary_fraction, progress):
    """Sample both turn directions independently of the forward-speed population."""
    rates = torch.zeros(count, device=device)
    progress = min(max(float(progress), 0.0), 1.0)
    if progress == 0.0 or fraction == 0.0 or low == high == 0.0:
        return rates
    if not (low < 0 < high and 0 <= minimum <= min(-low, high)):
        raise ValueError("Yaw training requires a range spanning zero and a valid minimum magnitude")
    if not (0 <= fraction <= 1 and 0 <= boundary_fraction <= 1):
        raise ValueError("Yaw fractions must be between zero and one")
    active = torch.rand(count, device=device) < fraction
    positive = torch.rand(count, device=device) < 0.5
    maximum = torch.where(positive, high, -low)
    magnitude = minimum + (maximum - minimum) * torch.rand(count, device=device)
    boundary = torch.rand(count, device=device) < boundary_fraction
    magnitude = torch.where(boundary, maximum, magnitude) * progress
    return torch.where(active, torch.where(positive, magnitude, -magnitude), rates)
```

函数先建零角速度 `[count]`。课程进度、启用比例或配置范围为零时直接返回，不执行后面的随机方向采样。正常训练要求 `low<0<high`，最小幅值不能大于任一方向的最大幅值；正负方向可各自有不同最大值。

`active` 决定哪些样本启用，`positive` 以 0.5 概率决定转向符号。`maximum` 针对符号选择 high 或 -low，`magnitude` 在 minimum 和该方向最大值之间均匀抽样，边界掩码再替换为最大幅值，最后整体乘 progress。

例如教学 raw minimum=0.1、progress=0.5，抽到最小幅值时物理 yaw 只有 0.05 rad/s；minimum 不是独立于课程的硬下限。后面还有总运动比例时，还要继续乘那个比例。实际使用哪个参数，应读取本次检查点保存配置。

### 12.4 `previous_speed` 为什么先 clone，最后又写回来

抽样器先保存 `previous_speed = _commands[env_ids,0].clone()`。接着可以生成一批新的最终速度、偏航和高度目标；最后把新前进速度放进 `_target_lin_vel_x`，再把 `_commands[:,0]` 恢复成之前的当前值。

这样 `_get_observations()` 中的斜坡可以继续从旧当前速度向新最终速度移动。若省掉最后的恢复，新目标会立即覆盖当前命令，加速度限制就失去原来的意义。

`clone()` 的作用是把旧值独立保存。如果只是保留一个指向可变缓存的视图，后面覆盖命令时，所谓“旧速度”也可能一起变化。

偏航和高度没有在这段实现里使用同一个 `_target_lin_vel_x` 斜坡。不要因为前进速度限制了变化率，就假定三种命令都受同样的加速度平滑。

### 12.5 固定站立 ID 与轮换运动角色怎样兼容部分 reset

`grouped_task_ids()` 的完整实现已在[构造阶段的首次调用](#first-call-grouped-task-ids)展开。再次使用时，仍以全局 `env_ids` 为准。前 K 个环境保持站立，其余 ID 在五个运动角色中根据全局 phase 轮换。

一个只包含 `[5,2000,7000]` 的部分重置批次，仍然根据这些真实 ID 判定角色；不能先重新编号为 `[0,1,2]`，否则本来属于运动组的机器人可能因局部序号较小而被当成固定站立组。

`phase=common_step_counter//重采样步数` 让整批运动任务同步轮换。它不依赖每台机器人可能不同的 `episode_length_buf`，所以某一台机器人提前 reset，不会把其他环境的任务角色同时重置。

这里的任务角色覆盖站立、原地转向和行进转向等一般任务类型。具体未验收测试工况用于诊断，不应因此往运行时添加某个固定高度或速度的补偿分支。

### 12.6 三种“课程进度”不是同一个变量

主运动进度控制前进任务启用和范围，后退进度控制后退范围，偏航进度控制角速度范围。`training_motion_scale` 又对抽到的线速度、角速度整体缩放，高度范围单独处理。

因此“缩放系数是 0.25”不等于每种动作都乘 0.25，也不等于高度命令缩到四分之一。四个腿动作的角度映射仍使用自己的 offset/scale；缩放作用的是任务命令分布。

训练、固定回放和诊断命令的路径也要区分。回放可以给定明确命令，但这不应被误记成随机抽样器在训练中已经覆盖了同样的每一个组合。

```python
def horizontal_velocity_error_squared(velocity, forward_command, lateral_multiplier=0.0):
    """Heading-frame vx tracking plus optional vy drift, for every command.

    Zero multiplier reproduces the legacy forward-only squared penalty.
    This is not a standing-only reward or a left/right wheel equality rule.
    """
    if velocity.ndim != 2 or velocity.shape[-1] != 2 or forward_command.shape != velocity.shape[:1]:
        raise ValueError('Expected horizontal velocity [N,2] and forward command [N]')
    if not math.isfinite(lateral_multiplier) or lateral_multiplier < 0:
        raise ValueError('Lateral velocity multiplier must be finite and nonnegative')
    return (forward_command - velocity[:, 0]).square() + lateral_multiplier * velocity[:, 1].square()
```

`velocity` 是 `[N,2]`，两列分别是已经在观测部分解析过的航向系前向/横向速度；`forward_command` 是 `[N]`。返回每台机器人的 `e_vx²+λ*v_y²`，所以形状是 `[N]`，没有沿环境维求平均。

λ=0 保持历史的前向平方误差；λ>0 时增加对横向漂移的代价，单位仍是 `(m/s)²`。这个函数对每个命令都计算，没有“只在站立生效”的掩码，也没有要求左右轮速相等。它是奖励信号，不会直接改轮速动作。

```python
def spin_center_velocity_penalty(wheel_velocities, wheel_radius, command_speed, target_speed, yaw_rate):
    """Penalize wheel common-mode motion only when a stationary spin is requested.

    Wheel coordinates must both be forward-positive. Equal opposite wheel speeds
    are valid for a centered spin; unequal speeds remain allowed during travel.
    """
    spinning = (command_speed.abs() < 0.01) & (target_speed.abs() < 0.01) & (yaw_rate.abs() > 0.05)
    center_velocity = wheel_radius * wheel_velocities.mean(dim=1)
    return center_velocity.square() * spinning
```

两列 wheel_velocities 已统一成前进为正，因此 `wheel_radius*mean(左右轮速)` 是理想轮运动的公共平移分量。等幅反向轮速的均值为零，符合原地旋转；前进转向本就需要非零公共分量，不应全部惩罚掉。

`spinning` 要求当前/最终线速度接近零、yaw 绝对命令大于 0.05 rad/s。函数返回公共分量的平方乘此掩码，不会强制两轮相等，也没有测量机身是否真正绕同一点旋转；真实平移还需机身水平速度和独立回放检查。尤其低于此 yaw 掩码的转向命令，不会由这一项提供约束。

### 13.2 高度指数奖励的跨文件计算

源码：[reward_signals.py](../../wheel_legged_gym_isaaclab/reward_signals.py#L65)，第 65 至 80 行。

<!-- source-excerpt: wheel_legged_isaaclab/wheel_legged_gym_isaaclab/reward_signals.py:65:80 -->

```python
def height_tracking_kernel(height, target, sigma, relative_deadband=0.0):
    """Do not trade failed motion tracking for already adequate height precision.

    Zero preserves historical checkpoints exactly. A nonzero inner band removes
    incentives to polish millimetres there; errors outside still receive a dense
    restoring reward. This is reward shaping, never an acceptance tolerance.
    """
    if not math.isfinite(sigma) or sigma <= 0:
        raise ValueError('Height reward width must be finite and positive')
    if not math.isfinite(relative_deadband) or not 0 <= relative_deadband < .1:
        raise ValueError('Height reward deadband must be smaller than ten percent')
    error = height - target
    if relative_deadband == 0:
        return (-error.square() / sigma).exp()
    excess = (error.abs() - relative_deadband * target.abs()).clamp_min(0.)
    return (-excess.square() / sigma).exp()
```

调用方传入当前机身高度 `height` 与命令高度 `target`，均为 `[N]`、单位 m；`sigma` 和 `relative_deadband` 是批次共用的配置标量。函数只返回每个环境的无量纲高度正奖励核 `[N]`，不修改命令、目标关节角或实际高度。后面的奖励装配还要乘 `base_height` 系数和控制步长。

前两条判断属于项目对奖励参数的约束：`sigma` 必须有限且大于零，避免除零或反向奖励；`relative_deadband` 必须有限且在 `[0,0.1)`，避免把奖励内部平坦带设得过宽。这些检查约束训练配置，不代表实际误差已经达标。

`error=height-target` 得到逐环境高度误差。当相对 deadband 为零，函数直接返回 `exp(−error²/sigma)`。sigma 的单位是 m²，不是米；`sqrt(sigma)` 才对应一种长度尺度。正负同等大小的误差给出相同结果。

以零 deadband 为教学例子，误差 0.02 m：

```text
sigma = 0.0004 时：exp(−0.02²/0.0004) = exp(−1) ≈ 0.3679
sigma = 0.0025 时：exp(−0.02²/0.0025) = exp(−0.16) ≈ 0.8521
```

后一条更宽，误差较大时仍有明显正奖励变化。它也会改变精细区域的奖励斜率，因此需要与平方惩罚、探索和姿态结果一起判断。

非零 deadband 时，`relative_deadband*target.abs()` 先计算每个环境的内部高度带宽，单位 m。`excess` 从绝对误差中扣除该带宽，再把负值裁成零：带内核值为 1，带外才按超出距离平滑衰减。这里是统一的相对误差公式，没有针对某个命令高度添加特例。

拿到返回张量后，回到当前 `_get_rewards()` 的高度信号计算；高度平方惩罚仍是独立信号，不由这个函数替代。奖励容差带也不是验收门槛，独立回放必须继续使用原判据。

```python
def action_second_difference_penalty(current, previous, older, wheel_multiplier=0.0):
    """Penalize reference chatter, not a constant wheel speed or balancing torque.

    Columns 0/1 and 3/4 are leg references in the selected control mode;
    2/5 are wheel references.
    A zero wheel multiplier reproduces the historical leg-only penalty.
    """
    if current.shape != previous.shape or current.shape != older.shape:
        raise ValueError("Action histories must have identical shapes")
    if current.ndim != 2 or current.shape[-1] != 6:
        raise ValueError("Expected a batch of six-dimensional applied actions")
    if not math.isfinite(wheel_multiplier) or wheel_multiplier < 0:
        raise ValueError("Wheel smoothness multiplier must be finite and nonnegative")
    difference = current - 2.0 * previous + older
    return (
        difference[:, (0, 1, 3, 4)].square().sum(-1)
        + wheel_multiplier * difference[:, (2, 5)].square().sum(-1)
    )
```

三个输入都是 `[N,6]` 的有效归一化动作。历史时间关系已在观测章节用三帧表说明；这里再次核对：current 为本步，previous 为上一控制步，older 为上上步。

`difference=current-2*previous+older` 为离散二阶差分。四个腿列直接求平方和，两个轮列再乘单独的 wheel_multiplier；λ=0 表示这一项只惩罚腿参考，λ>0 才对轮参考抖动计分。恒定参考的差分为零；每步等量递增的理想参考在非边界处也为零。

它没有除以 `step_dt²`，四个腿坐标也还没有乘关节角 scale，因而不是单位 rad/s² 的实际关节加速度。奖励里另有 `joint_acc` 物理状态项。返回值 `[N]` 后还要乘权重与 `step_dt`，再按本项裁剪，不能把数值直接解释成某种实物加速度限制。

```python
def wheel_action_overshoot_penalty(raw_actions):
    """Huber cost on discarded wheel outputs; zero throughout valid references."""
    if raw_actions.ndim != 2 or raw_actions.shape[-1] != 6:
        raise ValueError('Expected a batch of six raw policy actions')
    excess = (raw_actions[:, (2, 5)].clamp(-10., 10.).abs() - 1.).clamp_min(0.)
    near = excess.clamp(max=1.)
    return (.5 * near.square() + (excess - 1.).clamp_min(0.)).sum(-1)
```

调用方传 `_raw_actions`，因为若先用执行动作，超过包络的 1.1 与 3.0 都可能只剩 1，无法衡量被裁掉多少。函数只选轮列 `(2,5)`，先把参与奖励计算的 raw 裁到 ±10，再取绝对值、减 1，并把负数截成 0。

剩下 excess 在 `[0,1]` 内采用 `0.5*excess²`，超过 1 后采用线性尾部 `excess-0.5`，是连续衔接的 Huber 形式。最后只沿两轮求和，保留环境维；例如教学 raw=1.2 的单轮代价为 `0.5*0.2²=0.02`。

实现中的起罚点明确写为 1，函数没有接收 `wheel_action_limit`。因此“合法参考内代价都为零”的注释只对应单位动作包络；如果另一个已记录实验把轮包络扩大到 1.25，1～1.25 之间也可能被此项计分。当前是否实际影响学习还取决于本项权重，不能仅看函数名或注释判断已启用。本次文档核对不修改这条训练计算路径。

```python
def joint_target_length_error_squared(length_reference, height_command, height_offset):
    """Score direct motor-target FK against the requested upright leg length.

    This is a training reward, not IK or an action/height controller. The two
    sides are scored separately before averaging: an overlong leg cannot
    cancel an underlength leg. Do not apply the legacy VMC 0.32 m cap.
    """
    if (length_reference.ndim != 2 or length_reference.shape[-1] != 2
            or height_command.shape != length_reference.shape[:1]
            or not math.isfinite(height_offset)):
        raise ValueError('Expected two applied FK lengths, one height command and a finite offset')
    target = height_command[:, None] + height_offset
    return (length_reference-target).square().mean(-1)
```

先看调用外面的条件表达式：只有直接关节模式且配置系数非零，才调用函数；否则使用提前创建的 `[N]` 零张量。因此并非所有保存的模型都训练过这项奖励。

`length_reference=[N,2]` 来自四个已经限幅的电机目标角的正运动学，是目标参考的几何结果；它与实际腿长、实际世界高度是不同变量。`height_command[:,None]` 把 `[N]` 变为 `[N,1]`，加高度偏置后广播到左右两腿。

```python
def task_tracking_quality(height, command_height, gravity, criteria, floor):
    """Motion bonus quality, not acceptance or a command/action override.

    Full bonuses remain inside half of the ORIGINAL height/body tolerances.
    Smooth degradation outside does not zero motion learning: floor >= .05.
    """
    if height.ndim != 1 or command_height.shape != height.shape or gravity.shape != (*height.shape,3):
        raise ValueError('Expected one height/command and three gravity coordinates per environment')
    if type(floor) not in (int,float) or not math.isfinite(floor) or not .05 <= floor <= 1.:
        raise ValueError('Motion quality floor must remain finite in [.05,1]')
    relative, body_deg = criteria['relative_error'], criteria['body_p95_deg']
    if not all(math.isfinite(v) and v>0 for v in (relative,body_deg)):
        raise ValueError('Quality guard requires the original positive tracking criteria')
    height_ratio = (height-command_height).abs()/(relative*command_height.abs().clamp_min(.001))
    pitch = gravity[:,0].clamp(-1.,1.).asin().abs()
    roll = (-gravity[:,1]).atan2(-gravity[:,2]).abs()
    body_ratio = pitch.maximum(roll)/math.radians(body_deg)
    height_excess = (height_ratio-.5).clamp_min(0.)
    body_excess = (body_ratio-.5).clamp_min(0.)
    return floor+(1.-floor)/((1.+height_excess.square())*(1.+body_excess.square()))
```

高度两输入都是 `[N]`，重力为 `[N,3]`。`relative_error` 和 `body_p95_deg` 来自既有评估尺度，必须有限且大于零；这里用它们归一化单帧状态，不是在此重新计算一段轨迹的 P95。高度分母还有 0.001 m 的保护，避免极小目标导致除零。

`height_ratio` 为高度绝对误差相对允许高度尺度的比值。pitch 从重力 x 分量的 asin 得到，roll 从 `atan2(-g_y,-g_z)` 得到，取两者绝对值最大值后再除姿态角尺度，得到 body_ratio。

两种 ratio 都先减 0.5、再裁到非负：在两个半尺度以内 quality=1，越界后连续下降。公式 `floor+(1-floor)/((1+h_excess²)*(1+b_excess²))` 保证保留非零下限，而非突然把运动学习信号关掉。例如教学 floor=0.5、height_ratio=1、body_ratio≤0.5 时，quality=`0.5+0.5/1.25=0.9`。

返回外层，字典推导只给键 `track_lin_vel` 和 `track_ang_vel` 乘 quality，其他键保持原值。因此连 `track_lin_vel_enhance/precise` 也不在这个二键集合中；不能概括成“所有运动奖励都被同样缩放”。

调用所需 criteria 的构造依赖必须成立：基础环境只在 violation 项非零时加载；某些仅启用质量调制的实验通过 `joint_pd_quality_criteria_runtime.py` 补足依赖。后面的 §13.8 再核对这条实验入口，不应凭单个 floor 参数推断任何入口都已完成同样装配。

### 13.4 clip 到底裁剪什么

奖励先按各项规定的上限裁剪，再求和。`clip_single_reward=5` 对应普通单项每步上限约 `5×0.02=0.1`；姿态、偏航等负奖励可以有独立上限。

例如偏航平方惩罚权重 −200、误差 0.03 rad/s：

```text
每秒代价 = −200 × 0.03² = −0.18
每步代价 = −0.18 × 0.02 = −0.0036
```

若误差增大到使代价达到裁剪下限，再增大权重可能只扩大已饱和区域，并不继续改变那里的分数。优化前应先检查实际奖励分布，而不是只看权重数字。

```python
def _tracking_goal_error_ratios(commands, speed, yaw, height, gravity,
                                    length, length_reference, angle, angle_reference,
                                    wheels, wheel_reference, criteria):
    """Shared pointwise tolerances; the independent window gate is unchanged."""
    count = commands.shape[0]
    if (commands.shape != (count, 3) or gravity.shape != (count, 3)
            or any(value.shape != (count,) for value in (speed, yaw, height))
            or any(value.shape != (count, 2) for value in
                   (length, length_reference, angle, angle_reference, wheels, wheel_reference))):
        raise ValueError('Expected matched physical tracking batches')
    fraction = criteria['relative_error']
    speed_limit = (fraction * commands[:, 0].abs()).clamp_min(criteria['speed_absolute_m_s'])
    yaw_limit = (fraction * commands[:, 1].abs()).clamp_min(criteria['yaw_absolute_rad_s'])
    height_limit = fraction * commands[:, 2].abs().clamp_min(.001)
    length_limit = fraction * length_reference.abs().amin(-1).clamp_min(.001)
    wheel_limit = (fraction * wheel_reference.abs().amin(-1)).clamp_min(criteria['wheel_absolute_rad_s'])
    pitch = torch.asin(gravity[:, 0].clamp(-1., 1.))
    roll = torch.atan2(-gravity[:, 1], -gravity[:, 2])
    body = torch.maximum(pitch.abs(), roll.abs()) * (180. / math.pi)
    ratios = torch.stack((
        (speed - commands[:, 0]).abs() / speed_limit,
        (yaw - commands[:, 1]).abs() / yaw_limit,
        (height - commands[:, 2]).abs() / height_limit,
        (length - length_reference).abs().amax(-1) / length_limit,
        (angle - angle_reference).abs().amax(-1) / (fraction * criteria['leg_angle_design_range_rad']),
        (wheels - wheel_reference).abs().amax(-1) / wheel_limit,
        body / criteria['body_p95_deg'],
    ), dim=-1)
    return ratios
```

形状检查保证每个量按相同 N 对齐：commands/gravity 为 `[N,3]`，速度/yaw/高度各 `[N]`，左右腿和左右轮相关量各 `[N,2]`。输出 ratios 为 `[N,7]`，列顺序是线速度、yaw、高度、腿长、腿角、轮速、姿态。

速度、yaw 和轮速允许尺度保留原 absolute floor，避免零命令除零；高度按目标高度乘相对比例，腿长和轮速的双侧尺度使用较小参考绝对值，误差则取左右最坏值。腿摆角采用固定设计角范围乘相对比例，姿态是本帧最大绝对 roll/pitch 除 body_p95_deg。

这里用的是单帧误差及归一化尺度，代码没有计算 MAE 或 P95，也没有在此统计接触支撑或整段存活率。因此它只是训练侧密集代价，不能用 ratios≤1 替换独立轨迹验收，更不能说明持续窗口已经通过。

带着 ratios 返回外层，先取七列最大值、减 1 并裁到非负。只有超出允许尺度的部分被计分：excess≤1 时为 `0.5*excess²`，更大时接线性尾部。返回 `[N]` 后，调用方再乘非正系数和 `step_dt`，做本项负向裁剪，加入 rewards 字典并加到已经得到的 reward 总和。

```python
def tracking_goal_component_violation_penalty(commands, speed, yaw, height, gravity,
                                              length, length_reference, angle, angle_reference,
                                              wheels, wheel_reference, criteria):
    """Sum nonnegative Huber excesses so concurrent failures retain feedback.

    Passing components contribute zero and cannot cancel a failed component.
    This opt-in term supplements the worst-error feedback; neither term proves
    the independent MAE/P95 window acceptance or sustained verification.
    """
    ratios = _tracking_goal_error_ratios(
        commands, speed, yaw, height, gravity, length, length_reference,
        angle, angle_reference, wheels, wheel_reference, criteria)
    excess = (ratios - 1.).clamp_min(0.)
    near = excess.clamp(max=1.)
    return (.5 * near.square() + (excess - 1.).clamp_min(0.)).sum(-1)
```

它复用刚解释的七列 ratios，但没有先取最大值：每列分别求非负 excess 和同一 Huber 形式，最后沿七列求和。因此两项同时越界时都提供代价，已满足项贡献零，不会用一个“很好”的指标抵消另一个失败指标。

返回调用方以后，同样乘该项独立系数、时间步和负向上限，再补进 reward。两个系数为零时这两条分支均跳过，函数虽然被导入也不会执行。最后 `_last_reward_terms` 保存 detach 后的实际分项，各 episode 累加器累加本步贡献，最终才返回 `[N]` 总奖励。


### 13.6 `signals`、`rewards` 和 `_last_reward_terms` 是三层含义

`signals` 中保存没有乘权重的物理误差或核函数，例如角速度误差平方。`rewards` 在这些信号上乘对应配置系数与 `step_dt`，再做各项裁剪。

`_last_reward_terms` 保存该步用于诊断的各项实际奖励分量。它适合核对“这一项到底有多大”，不能仅凭配置中的负权重数值就推断它比其他项重要多少。

例如 −50 乘上的若是 `0.01²`，结果大小与 −1 乘上 1 完全不同；还必须计入时间步长、裁剪和某些信号自己的条件掩码。

`REWARD_SCALE_FIELDS` 把 `track_ang_vel` 等运行时日志键映射到 `tracking_ang_vel` 这类配置名。`getattr(cfg.rewards, mapped_name)` 动态读取真正系数，因此查 reward 时要同时看字典键和配置字段，而不能只搜索一个字符串。

### 13.7 站立水平速度代价不等于站立偏航速度代价

当前 `standing` 首先由当前/最终线速度命令判断；`r_standing_velocity` 对 `heading_velocity` 的两列水平速度求平方和，没有把 `root_ang_vel_b[:,2]` 直接加进去。

因此纯转向时，这一项可以抑制机身平移，却不是一个直接要求 yaw=0 的角速度惩罚。车轮参考跟随的站立项还额外要求偏航命令接近零，条件与前一项不同。

排查偏航欠跟随时，应按实际公式核对这些掩码和输入。不能只因为名字含 standing，就认定所有原地转向都被当成应当禁止的动作。

### 13.8 姿态/高度质量权重怎样作用于运动正奖励

`guard_tracking_bonuses()` 与嵌套质量函数已在[首次调用处](#first-call-guard-tracking-bonuses)逐段展开。这里补充它所需 criteria 在实验入口中的装配；只有键 `track_lin_vel/track_ang_vel` 受调制。

当质量系数下限为 1 时，辅助函数直接返回原 signals；小于 1 时才使用原验收高度和姿态尺度计算连续质量。这是在奖励侧表达任务优先级，不是在动作侧加入高度反馈或关节角修正。

这里有一个必须读到实际入口的细节：主环境构造函数只在可选 violation 项非零时加载 `_tracking_goal_criteria`，而某些实验会保持 violation 为零、仅启用质量权重。

这些实验通过 [joint_pd_quality_criteria_runtime.py](../../../mine_model/experiments/joint_pd_quality_criteria_runtime.py) 在构造时补足 criteria 依赖。不能只复制一个 `floor<1` 的 CLI 参数，就假定绕过该实验入口以后基础构造函数也已经执行了相同补充。

学习框架时应把“基础任务默认路径”和“本项目某实验明确安装的运行时依赖修正”分开追踪。这里说明的是当前实际执行链，不把一项实验配置当作框架所有入口天然具备的能力。

### 13.9 episode 日志为什么不能直接当作整回合的真实平均误差

`_episode_sums[key]` 累加的是奖励贡献。reset 时除以 `max_episode_length_s`，得到便于比较的奖励统计，并不是把每一个物理误差换算成了百分比。

某回合提前失败时，它仍然按配置的最大回合秒数作这个日志归一化，不能据此把数值解释成“这个短回合每秒实际误差”。独立误差计算应读取轨迹中的命令、状态、有效窗口和存活情况。

`extras['log']` 最后还会合并本步诊断。[首次观测返回处](#first-call-merge-step-diagnostics)已展开 `merge_step_diagnostics()`；它返回一份新字典，避免 reset 替换日志或 runner 把某些日志值转成 Tensor 时，不小心污染下一步复用的诊断缓存。

### 14.1 每一类失败都有自己的连续计时

源码：[wheel_legged_vmc_flat_env.py](../../wheel_legged_gym_isaaclab/tasks/direct/wheel_legged_vmc_flat/wheel_legged_vmc_flat_env.py)，第 964 至 971 行。

```python
def _advance_failure_counter(self, counter, unsafe, seconds, *, inclusive=False, minimum_steps=None):
    """Count continuous unsafe steps; a safe step clears only this timer."""
    counter = torch.where(unsafe, counter + 1.0, 0.0)
    threshold = seconds / self.step_dt
    if minimum_steps is not None:
        threshold = max(minimum_steps, threshold)
    died = counter >= threshold if inclusive else counter > threshold
    return counter, died
```

`torch.where(unsafe,counter+1,0)` 表示连续危险才累加。`seconds/step_dt` 把时间阈值换成控制步数。

严格大于和大于等于的分支会导致边界相差一个控制步。例如 0.15/0.02=7.5，不会恰好等于一个整数计数，实际触发需要结合比较符号判断。

### 14.2 数值和运动学失败不能靠观测清洗隐藏

`_get_dones()` 单独检查根部、关节和接触力是否有限，并检查 `_five_bar_valid`。即使 `_sanitize_observation()` 能把 NaN 变成零，数值失败也不能因此被当成正常环境。

最终 `died` 是多个失败原因的或；`time_out` 则由回合长度产生。框架将这两种结束分开返回，后面 wrapper 和 PPO 会据此处理超时价值补偿。

### 14.3 连续不安全计时与累计出现次数的区别

`torch.where(unsafe,counter+1,0)` 使某一类风险只要出现一个安全步，就清掉该类连续计时。因此“碰撞两步、安全一步、再碰撞两步”的计数不是四步。

每类风险都有自己的 counter，避免一次腿部接触把机身翻倒的计时一起清掉，或把本来不连续的不同故障拼成同一段持续风险。

默认 `>` 与 `inclusive=True` 的 `>=` 也有边界差异。例如 `seconds/step_dt=3`，前者到第 4 个连续不安全控制步才触发，后者到第 3 个便触发。这个控制步是 0.02 s，不是 0.005 s。

`minimum_steps=1.0` 为某些风险规定至少一个控制步的判断门槛。它不等于修改几何高度阈值，也不涉及 PPO 总训练何时结束。

### 14.4 当前状态字段与运动学缓存的更新时间

`_get_dones()` 在四次物理子步以后读取机器人和接触传感器状态；但 `_five_bar_valid` 来自此前的正运动学缓存。正常 `_apply_action()` 会在每次子步施力前更新它，`_get_rewards()` 随后还会再次更新 FK。

因此不能只凭函数名字就假定所有风险信号都在 `_get_dones()` 内重新计算到完全相同物理时刻。按当前代码顺序，运动学有效性缓存与最后一次物理推进之间有更新时间差。

如果要研究极短的奇异瞬态，必须把这个缓存时序一起记录。本文描述现有顺序，不为了教学改动正在运行的物理或终止代码。

### 15.5 重置不是 PPO 清空全部经验

某个环境结束时，其新回合可以继续填入同一批 rollout。storage 中的 done 掩码让 GAE 不把价值递推穿过不安全终止。

PPO 不是等所有 4096 个环境同时完成一个回合后才更新。它每次收集固定 48 个控制步，不同环境可以处于不同回合年龄。

### 15.6 `reset()`、写实际状态、写目标分别沿哪条链运行

`self._robot.reset(env_ids)` 清理执行器等内部缓存，父类 `_reset_idx()` 再重置场景、事件、噪声与 episode 计数。它们本身不等于已经把所有刚体搬回初始姿态。

随后 `write_root_pose_to_sim()` 和 `write_root_velocity_to_sim()` 才把根部姿态、速度写入物理状态；`write_joint_state_to_sim()` 写关节实际状态。此处关节列表传 None，表示要恢复选中机器人的全部关节，包括被动闭链关节。

若只恢复四个主动关节而不考虑被动关节，重置瞬间的几何状态可能与闭链约束不一致。`configure_reset_pose()` 准备完整默认模板，就是为了让这条状态写回链有一致起点。

恢复实际状态后仍要清理旧目标。直接模式把四个角目标恢复到 offset，腿速度参考设零，显式 effort 清零；否则下一次场景提交仍可能使用上回合留下的饱和目标。

### 15.7 `clone()` 为什么在重置模板上特别重要

默认根状态和默认关节状态是其他 reset 还要继续使用的模板。选出当前 env 行以后再 `clone()`，才能在临时结果上加环境原点、写速度扰动，而不污染模板。

`default_root_state[:,:3] += env_origins[env_ids]` 把相对场景原点的位置换成世界位置。这里是在 xyz 三列加同一组环境原点，没有给四元数或速度列加平移量。

十三维 root state 的四元数排列是 wxyz，后六列是世界线速度和世界角速度。对这六列加随机初始化速度，与给机器人施加一个持续外力不同，也不能把 rad/s 的角速度扰动直接当成 m/s。

### 15.8 为什么重置前先保存旧命令

函数开头 clone 旧的当前速度、最终速度和高度命令，是为了在后面清命令、重新抽样之后，仍能把这次结束归到原来执行的任务上。

如果等 `_resample_commands_for()` 以后再读取命令，日志会拿到新回合的新目标，可能把一次高速后退故障错误标记成新抽到的站立或前进任务。

`steps_since_resample` 同样在清理前计算，供“是否发生在命令切换后短时间内”诊断使用。它是诊断分组，不会按某种工况替换 Actor 动作。

### 15.9 reset 后返回的 observation 与本步 reward 为什么不矛盾

发生失败的那一步，`reward` 和 `terminated` 对应旧回合最后一次动作；该行随后已 reset，所以返回的 observation 来自新回合。

RolloutStorage 保存旧 observation、旧 action、本步 reward 和 done。GAE 利用 done 掩码停止跨越不安全终止的递推，因此不应该为了“看起来对应同一姿态”把已失败 reward 改成新回合的初始 reward。

超时是另一种结束原因，wrapper 会通过 `time_outs` 提供附加信息。本机 RSL-RL 的超时补偿作用及输入输出，在第三篇的反馈接口说明中继续衔接。

## 十六 把一次交互从头连起来

以一个环境的一步为例：Actor 根据 27 维观测输出六个 Gaussian 动作；环境保留 raw 输出、限制执行动作；四个腿动作变为关节角目标，两轮动作变为轮速目标；四个物理子步更新驱动与前馈；最后根据实际运动计算奖励和失败。

若这个环境没有结束，下一帧观测描述它继续运动的状态。若结束，reward 和 done 仍描述刚刚失败的那一步，下一帧 observation 则来自重置后的新回合。

这批数据随后由 `RslRlVecEnvWrapper` 转成 RSL-RL 接口，再进入 `PPO.process_env_step()` 和 `RolloutStorage`。下一篇继续说明这批数据怎样交给 PPO 库采样与更新，以及应用层应核对哪些输入和结果。
